# 像素沙盒世界 - 主规范文档

> 本文档是项目的核心规范总览，所有开发必须以此为准。

---

## 项目概述

开发一个像素风的自由沙盒世界（类似《边缘世界 RimWorld》或《斯坦福小镇》）。

### 核心诉求
- 支持 100+ 智能体（NPC）同时运行
- 底层采用**纯代码驱动的效用AI**，节省API费用和降低延迟
- 仅在玩家围观或重要剧情时开启**LLM接管**
- 所有配置文件和数据结构字段名均使用**中文**

### 技术栈
| 层级 | 技术 |
|------|------|
| 表现层 | HTML5 Canvas API |
| 编程语言 | TypeScript（编译为JavaScript） |
| 构建工具 | 演示：`web/map-demo` 使用 Vite；主工程待定 |
| 数据格式 | JSON |

**迁移说明**：架构设计支持未来迁移到Unity/Godot等引擎，核心逻辑与渲染层分离。

## 系统架构 (MVC)

```
┌─────────────────────────────────────────────────────────┐
│                      UI (表现层)                         │
│  - 仅负责调用API获取"世界快照"并渲染像素画面              │
│  - 绝对不参与任何逻辑计算                                │
└─────────────────────────────────────────────────────────┘
                           │
                           ▼
┌─────────────────────────────────────────────────────────┐
│                     API (接口层)                         │
│  - 引擎向外暴露的交互点                                  │
│  - 提供世界快照、角色操作等接口                          │
└─────────────────────────────────────────────────────────┘
                           │
                           ▼
┌─────────────────────────────────────────────────────────┐
│                   Engine (引擎层)                        │
│  - 基于Tick推演智能体思考、移动、物品流转                │
│  - 效用AI决策系统                                       │
│  - 时间系统管理                                         │
└─────────────────────────────────────────────────────────┘
                           │
                           ▼
┌─────────────────────────────────────────────────────────┐
│                   Storage (存储层)                       │
│  - 所有数据的JSON本地持久化与读写                        │
└─────────────────────────────────────────────────────────┘
```

## 源代码目录（与 docs 分离）

| 路径 | 说明 |
|------|------|
| `web/map-demo/` | 世界地图网格浏览器演示（100×100）；**无 Node 时**可直接打开目录内 `standalone.html`，有 Node 时用 Vite（细则见 [世界系统.md](../01-系统规范/世界系统.md)「地图演示程序」） |
| `docs/` | **仅**规范与说明文档，不存放游戏业务源代码 |

**原则**：规范与代码**双向映射**——改规范须同步改实现，改实现若影响行为契约也须回写规范；二者**分目录存放**，禁止把源码塞进 `docs/`。

## 设计原则

### 1. 兼容性优先
- 所有模块设计必须预留扩展接口
- 新增功能不应破坏现有代码
- 配置驱动，而非硬编码

### 2. 标签驱动 (Tag-driven)
- 万物皆可标签化
- 通过标签匹配实现灵活交互

### 3. 中文优先
- 所有JSON字段名使用中文
- 所有配置文件使用中文
- 便于非技术人员理解和修改

### 4. 效用AI核心
- 不写死固定对话或行为
- 通过计算动态涌现行为
- 性格系统影响决策权重

## 数据文件清单

| 文件名 | 说明 |
|--------|------|
| 角色数据.json | 所有NPC的数据 |
| 物品数据.json | 所有物品的数据 |
| 世界数据.json | 地图、建筑数据 |
| `NPC/*.json` | **每个 NPC 一条主档案**（文件名建议与 `角色id` 一致）；扩展数据可放 `NPC/{角色id}/`；见 [角色系统.md](../01-系统规范/角色系统.md)「NPC 单文件存储」 |
| personality_base.json | 性格维度定义 |
| 配置.json | 全局配置（Tick时长等） |

> 地图演示的走格间隔、屏幕卷边距等常量见 `web/map-demo/src` 实现；正式游戏应由 `配置.json` 或引擎默认值驱动。
