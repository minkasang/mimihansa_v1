## 一、分析方法论

### 1.1 链路追踪法

本文档采用**真实人生链路追踪**方法，沿着5条核心链路逐步推演：

1. **第一天生存**：30-40个NPC醒来→找水→找食物→搭庇护所
2. **从出生到成年**：婴儿出生→被照料→上学→成年
3. **从相识到结婚**：注意到异性→搭讪→积累好感→追求→结婚
4. **经济自运转**：生产→定价→交易→消费→产业链
5. **从原始到文明**：发明工具→农业→分工→社会结构

### 1.2 断裂点定义

**断裂点** = 链路中某一步骤在文档中有描述，但在实际可运行系统中缺少对应的机制/数据/代码支撑，导致链路无法继续推进。

## 三、第一层：引擎层缺失（3项）

### 3.1 子目标链机制（Sub-Goal Chain）

**问题描述**：
当前引擎是单层决策：欲望→目标→动作→结束。但真实生活的决策是嵌套的。例如"饿了→想吃→没食物→去找→采摘→吃"需要4层子目标拆解。

**当前状态**：
- GOAPPlanner存在，但只支持单层动作序列
- 动作库没有提供足够的"前提条件→效果"对来支持反向链搜索
- NPC遇到"前提条件不满足"时直接卡死，不会自动生成子目标

**需要的机制**：
```typescript
interface Goal {
  id: string;
  preconditions: Condition[];      // 前提条件
  effects: Effect[];               // 达成效果
  subGoals?: Goal[];               // 子目标链（动态生成）
  actions?: Action[];              // 原子动作（叶子节点）
}

// 示例：吃食物的子目标链
goal_eat_food:
  preconditions: ["有食物在背包"]
  effects: ["饥饿度-4"]
  subGoals: [
    {
      id: "获取食物",
      preconditions: [],
      effects: ["有食物在背包"],
      subGoals: [
        {
          id: "去采摘",
          preconditions: ["知道野果位置"],
          actions: ["move_to_forest", "action_forage"]
        },
        {
          id: "去购买",
          preconditions: ["有钱", "知道商店位置"],
          actions: ["move_to_shop", "action_buy"]
        }
      ]
    }
  ]
```

**影响链路**：所有需要"准备才能做"的行为（第一天生存、经济运转、文明起步）

**优先级**：P0（不补无法运行）

---

### 3.2 持续性意图栈（Persistent Intent Stack）

**问题描述**：
当前引擎每5-10 Tick重新计算所有欲望，选最高的执行。但真实生活中有很多持续性意图（追求某人、攒钱买房、学技能），这些意图应该持续数周到数月，压制短期欲望。

**当前状态**：
- 没有"长期意图"概念
- "追求小美"和"晒太阳"平等竞争，追求可能被晒太阳打断
- 没有意图进度追踪

**需要的机制**：
```typescript
interface PersistentIntent {
  id: string;
  type: "追求" | "学习" | "攒钱" | "储备" | "建造";
  target: any;                     // 目标对象（NPC/技能/物品）
  priority: number;                // 1-10，压制短期欲望的阈值
  progress: number;                // 0-100，进度百分比
  subGoals: Goal[];                // 当前阶段的子目标
  createdAt: number;               // 创建时间
  deadline?: number;               // 截止时间（可选）
  
  // 生命周期
  onCreate(): void;
  onProgress(delta: number): void; // 进度更新
  onComplete(): void;
  onAbandon(reason: string): void; // 放弃条件
}

// 意图栈管理
class IntentStack {
  intents: PersistentIntent[];
  
  // 每Tick检查：高优先级意图压制低优先级欲望
  shouldSuppress(shortTermDesire: Desire): boolean {
    return this.intents.some(i => i.priority > shortTermDesire.priority);
  }
}
```

**影响链路**：恋爱婚姻（追求）、童年教育（上学）、经济（攒钱）、农耕（储备过冬）

**优先级**：P1（不补只有生存没有社会）

### 3.3 感知→欲望映射（Perception-Action Loop）

**问题描述**：
当前感知系统是"被动的"——每Tick更新感知结果，但不直接驱动行为。真实生活中，感知直接触发欲望：听到哭声→去看看，闻到香味→想吃。

**当前状态**：
- PerceptionResult[]存在，但欲望计算主要依赖NPC自身状态
- 只有`want_chat_up`和`want_socialize`检查了感知条件
- "听到哭声""闻到香味""看到别人在建房子"没有对应的欲望触发

**需要的机制**：
```typescript
interface PerceptionTrigger {
  perceptionType: "视觉" | "听觉" | "嗅觉" | "触觉";
  filter: (perception: PerceptionResult) => boolean;  // 过滤条件
  generateDesire: (npc: NPC, perception: PerceptionResult) => Desire | null;
  priority: number;
  cooldown: number;                // 冷却时间，防止重复触发
}

// 示例触发器
const triggers: PerceptionTrigger[] = [
  {
    // 听到婴儿哭声→产生照顾冲动
    perceptionType: "听觉",
    filter: p => p.类型 === "哭声" && p.来源 === "婴儿",
    generateDesire: (npc, p) => {
      if (npc.道德.同理心 > 5) {
        return { id: "want_check_crying", target: p.source };
      }
      return null;
    },
    priority: 8,
    cooldown: 300  // 5分钟内不重复触发
  },
  {
    // 闻到烤肉香味→产生食欲
    perceptionType: "嗅觉",
    filter: p => p.类型 === "食物香味",
    generateDesire: (npc, p) => {
      if (npc.生理.饥饿 > 5) {
        return { id: "want_eat", target: p.source };
      }
      return null;
    },
    priority: 7,
    cooldown: 600
  }
];
```

**影响链路**：婴儿照料、社交互动、模仿学习、环境响应

**优先级**：P1

## 五、第三层：效果系统缺失（5项）

### 5.1 效果路由扩展

当前效果路由表只支持：
- 数值加减（`{"饥饿": -3}`）
- 物品增减（`{"物品栏": "+苹果"}`）

**需要新增的效果类型**：

```typescript
// 1. 好感度效果（需要附带target参数）
{
  "好感度": {
    "target": "$目标NPC_ID",
    "value": 20,
    "operation": "add"
  }
}

// 2. 标签增删效果
{
  "标签": {
    "operation": "add" | "remove",
    "tags": ["情侣", "夫妻"]
  }
}

// 3. 实体生成效果
{
  "生成实体": {
    "类型": "建筑" | "火堆" | "尸体",
    "位置": [x, y],
    "属性": { ... }
  }
}

// 4. 知识库写入效果
{
  "知识库": {
    "operation": "add",
    "条目": {
      "类型": "地点" | "人物" | "事件",
      "内容": "...",
      "可信度": 0.8
    }
  }
}

// 5. 关系变更效果
{
  "关系": {
    "target": "$目标NPC_ID",
    "关系类型": "配偶" | "父母" | "子女",
    "operation": "set" | "remove"
  }
}
```

**优先级**：P0（所有社交/建造/死亡系统都依赖这些效果）

### 5.2 多Agent协作机制

**问题描述**：
当前引擎每个NPC独立决策，没有协作机制。但现实中很多行为需要多人配合：合作建造、围猎、选举、调解纠纷。

**需要的机制**：

```typescript
interface MultiAgentAction {
  id: string;
  requiredParticipants: number;      // 需要的人数
  maxParticipants: number;           // 最多人数
  
  // 发起阶段
  initiate(initiator: NPC): boolean;  // 发起者发起
  invite(target: NPC): boolean;       // 邀请他人
  acceptInvitation(npc: NPC): boolean; // 接受邀请
  
  // 执行阶段
  execute(participants: NPC[]): void; // 多人同时执行
  
  // 收益分配
  distributeRewards(participants: NPC[]): void;
}

// 示例：合作建造
const cooperativeBuilding: MultiAgentAction = {
  id: "coop_build_house",
  requiredParticipants: 2,
  maxParticipants: 4,
  
  initiate(initiator) {
    // 检查发起者是否有建筑技能
    return initiator.技能.建筑 > 3;
  },
  
  invite(target) {
    // 目标是否愿意帮忙？
    return target.性格.友善 > 5 && target.当前空闲;
  },
  
  execute(participants) {
    // 建造时间 = 基础时间 / 人数
    const buildTime = 1000 / participants.length;
    // 每人获得建筑技能提升
    participants.forEach(p => p.技能.建筑 += 0.1);
  }
};
```

**优先级**：P2（锦上添花，不补也能跑基础版本）

## 七、实施建议：分阶段补齐

### 阶段一：生存闭环（让NPC活过第一天）
**目标**：补齐第一天生存链路的所有断裂点

**必须完成**：
1. 子目标链机制（引擎层）
2. want_drink + action_drink
3. want_forage + action_forage
4. want_build_shelter + action_build
5. 实体生成效果（建筑生成）
6. 知识库写入效果（水源位置、野果位置）

**验证标准**：
- 30个NPC运行1天（游戏时间）后，存活率>80%
- 至少50%的NPC成功搭建庇护所
- 没有人因口渴/饥饿死亡

---

### 阶段二：社会闭环（让NPC能结婚生子）
**目标**：补齐从出生到结婚链路的所有断裂点

**必须完成**：
1. 持续性意图栈
2. 感知→欲望映射（哭声响应）
3. want_care_for_child + action_feed_child
4. want_send_child_to_school
5. 好感度效果路由
6. 标签增删效果（情侣/夫妻标签）

**验证标准**：
- 婴儿出生后能存活到成年
- 至少一对NPC能完成从相识到结婚的全过程
- 学校系统能正常运转（有学生上学）

---

### 阶段三：经济闭环（让经济自运转）
**目标**：补齐经济链路的所有断裂点

**必须完成**：
1. want_buy_food / want_sell_goods
2. want_trade_p2p
3. 多Agent协作机制
4. 价格预期机制（NPC对合理价格的认知）

**验证标准**：
- 存在至少3个活跃的商店
- 存在至少10次成功的P2P交易
- 货币在经济体内循环（不是单向流动）

---

### 阶段四：文明闭环（从原始到文明）
**目标**：补齐文明演进链路的所有断裂点

**必须完成**：
1. want_make_fire + want_craft_tool
2. want_hunt + want_cook
3. want_explore
4. want_stockpile_for_winter
5. 发明机制数据驱动化

**验证标准**：
- 有人发明石刀
- 有人建立农田
- 有人建造仓库储备过冬
- 出现简单的社会分工（农民/猎人/工匠）

## 八、核心设计原则提醒

在补齐这些缺失环节时，必须遵守以下原则：

### 8.1 数据驱动原则
所有新增的欲望、动作、效果都应该通过JSON配置，而不是硬编码。例如：
- ❌ 错误：`if (npc.智商 > 7) { 发明石刀() }`
- ✅ 正确：在`Inventions_Library.json`中定义发明的触发条件和效果

### 8.2 最小侵入原则
新增机制应该复用现有引擎架构，不要推翻重来：
- 子目标链应该基于现有的GOAPPlanner扩展
- 持续性意图应该基于现有的欲望系统扩展
- 效果系统应该基于现有的效果路由表扩展

### 8.3 可验证原则
每个补齐的环节都应该有明确的验证标准：
- 欲望：触发条件是否可达？动作序列是否能完成？
- 效果：是否能正确修改状态？是否有副作用？
- 机制：是否能支撑完整的链路？

## 十一、第四层：数据结构层缺失（5项）—— 优先级P0

### 11.1 NPC完整TypeScript interface未定义

**问题描述**：
NPC参数总表列了14大类、100+个参数，但**没有定义一个完整的 TypeScript interface**。文档用表格行描述参数，但：

- 参数之间的**嵌套层级**不明确。效果路由表写的是`生理状态.饥饿度`，但现有代码里NPC的JSON是扁平结构（`"饥饿": 8`）
- 哪些参数是**持久化字段**（存JSON）、哪些是**运行时计算值**（每Tick算一次）没有区分
- "择偶偏好"是每个NPC独立的数据结构（3项偏好+权重），但参数总表只写了一行"择偶偏好 | 每个NPC的偏好列表(3项)"——**数据结构完全没定义**
- 好感度是`社会关系.好感度[目标NPC_ID]`的字典结构，但参数总表里没有这个字段

**代码后果**：效果路由表里的路径`NPC.生理状态.饥饿`无法映射到实际JSON字段`npc.饥饿`，效果结算器找不到目标。

## 十四、第七层：事件系统缺失 —— 优先级P1

### 14.1 跨系统触发链没有统一的事件机制

**问题描述**：
文档里大量描述了"A发生→触发B"的因果链，但没有定义**事件系统**：

| 触发链 | 来源文档 | 谁检测？谁触发？ |
|--------|---------|----------------|
| 好感度骤降>15 → 60%概率打架 | 农耕系统 | ❓ |
| 孕期≥300天 → 分娩 | 出生系统 | ❓ |
| 人口≥20 → 触发选举 | 村落治理 | ❓ |
| 偷窃被发现 → 老板记忆标签 | 职业系统 | ❓ |
| 饥饿度≥8 → [饥饿风险]标签 | 标签规范 | ❓ |
| NPC死亡 → 房子变无主 → 配偶变寡妇 → 子女变孤儿 | 死亡系统 | ❓ |
| 建筑完工 → 居住者搬入 | 建房系统 | ❓ |
| 作物成熟 → 农民去收割 | 农耕系统 | ❓ |

**当前状态**：IO注册表只管"谁读写什么字段"，不管"谁监听什么事件"。每个系统自己写`if (xxx) { do yyy }`，散落在各处。

**需要新增**：
```typescript
interface GameEvent {
  类型: string;             // "NPC死亡" | "建筑完工" | "好感度变化" | ...
  来源: string;             // 触发者ID
  目标?: string;            // 目标ID
  数据: Record<string, any>;
  时间戳: number;
}

class EventBus {
  private listeners: Map<string, Function[]>;
  
  on(eventType: string, callback: (event: GameEvent) => void): void;
  emit(event: GameEvent): void;
  off(eventType: string, callback: Function): void;
}

// 注册示例
eventBus.on("NPC死亡", (event) => {
  // 处理房产继承
  // 处理配偶状态
  // 处理子女状态
  // 处理工作交接
});
```

**优先级**：P1

### 14.2 死亡级联效应没有处理机制

**问题描述**：
NPC死亡是一系列级联事件的起点，但当前没有任何机制处理这些级联：

```
NPC死亡
  → 房子变无主建筑（需要更新Building.所有者ID）
  → 配偶变寡妇（需要更新配偶的社会关系.配偶ID、添加[寡妇]标签）
  → 子女变孤儿（需要更新子女的社会关系.父母ID、添加[孤儿]标签）
  → 工作岗位空缺（需要更新Building.扩展数据.教师ID等）
  → 财产分配（金钱/物品给继承人）
  → 尸体生成（在原位置生成Corpse实体）
  → 他人记忆更新（认识此NPC的人获得"XX已死"的知识）
  → 村落人口更新（WorldState.人口-1）
```

这些步骤涉及6个不同的系统（建筑、社交、职业、经济、感知、世界状态），没有事件系统就无法协调。

**优先级**：P1

## 十五、第八层：动物系统集成缺失 —— 优先级P1

### 15.1 引擎只支持NPC，动物无法接入

**问题描述**：
动物系统文档说"动物走同一个决策循环：感知→欲望→选最高分→执行指令→效果结算"。但当前引擎的BrainEngine是**硬绑NPC数据结构**的：

- DesireEvaluator读的是NPC的生理状态/性格/物品栏
- ScoreCalculator读的是Brains_Library.json（34维性格打分）
- GOAPPlanner输出的指令序列引用的是NPC的ModuleRegistry

动物没有34维性格、没有技能、没有书生气——**动物的欲望库、动作库、打分方式完全不同**。

**需要新增**：
```typescript
// Agent抽象基类
interface Agent {
  id: string;
  位置: [number, number];
  当前动作: string;
  
  // 决策接口
  getDesires(): Desire[];
  evaluateDesires(): Desire;
  planActions(desire: Desire): Action[];
  executeAction(action: Action): void;
}

// NPC实现Agent
class NPCAgent implements Agent { ... }

// Animal实现Agent
class AnimalAgent implements Agent {
  // 动物专属欲望库（只有5-10条基础欲望）
  // 动物专属动作库（移动/吃/攻击/逃跑/休息）
  // 动物专属打分（基于攻击性/警觉性/群居性，不用34维性格）
}
```

**优先级**：P1

### 15.2 狼群群体行为超出单Agent决策模型

**问题描述**：
动物系统设计了狼的群体行为：共享感知、协同攻击、首领指挥。但当前引擎是**单Agent独立决策**——每只狼自己决定做什么，没有"群体意图"概念。

**需要新增**：群体行为机制（GroupBehavior），群体共享感知结果，首领的决策影响群体成员。

**优先级**：P2

## 十六、现有代码的具体Bug和不匹配

### 16.1 action_搭讪效果"社交值"字段不存在

**问题描述**：
Actions_Library.json中action_搭讪的效果写的是`"社交值": "+15"`——但NPC参数总表里**没有"社交值"这个字段**。恋爱系统定义的好感度是`社会关系.好感度[目标ID]`，但效果格式`{"社交值": "+15"}`无法路由到这个字段。

**修复**：效果应该写成`{"好感度": {"target": "$目标NPC_ID", "value": 15}}`，但这需要效果系统先支持好感度路由（见§5.1）。

**优先级**：P0

---

### 16.2 want_eat触发阈值太高，第一天NPC不会觅食

**问题描述**：
want_eat的触发条件是`饥饿>7`。假设饥饿度从5开始，每Tick加0.05，需要40个Tick（40秒）才到7。到了7之后，NPC执行action_eat——但这个动作是"消耗背包里的食物"。**第一天NPC背包是空的**，没有食物可吃。

**修复**：
- 降低want_eat触发阈值到5，或
- 新增want_forage（饥饿>5且背包无食物时触发），作为want_eat的子目标

**优先级**：P0

---

### 16.3 want_sleep引用"$家坐标"但无家NPC没有回退行为

**问题描述**：
want_sleep的指令序列包含`move_to("$家坐标")`，但第一天NPC没有家，`家坐标=null`。移动到null位置会导致崩溃或NPC原地不动永远无法睡觉。

**修复**：
- 无家NPC应该"在原地睡觉"（效果打折：疲劳恢复-50%）
- 或触发子目标"找地方睡觉"→如果有庇护所就去，没有就原地睡

**优先级**：P0

---

### 16.4 效果路由表路径与实际JSON字段不匹配

**问题描述**：
效果路由表写的是`NPC.生理状态.饥饿`，但实际NPC的JSON是扁平结构`npc.饥饿`。路径不一致导致效果结算器找不到目标字段。

**修复**：统一路径格式。要么改效果路由表，要么改NPC的JSON结构为嵌套。建议改JSON为嵌套结构（与§11.1对齐）。

**优先级**：P0

---

### 16.5 经济启动的"鸡生蛋"问题

**问题描述**：
- 谁第一个去磨石刀？需要`want_craft_tool`欲望——不存在
- 磨好石刀后，谁去买？没有买方
- 没有买方→没有市场→没有价格→经济系统无法启动

经济的启动需要一个"破局点"——比如初始世界就有1-2个NPC自带基础工具和交易意愿，或者"发明"机制在第一天就触发。但文档没有设计这个破局机制。

**优先级**：P1
