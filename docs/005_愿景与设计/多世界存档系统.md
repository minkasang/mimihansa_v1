﻿﻿﻿﻿# 多世界存档系统

> ⚠️ 规范研究文档。定义游戏存档的目录结构、命名规则、加载/保存/切换流程。
> 玩家可以拥有多个独立世界，每个世界的 Tick、地图、NPC 数据完全隔离。

---

## 一、目录结构

```
shapan2/
├── saves/                          # 所有存档的根目录
│   ├── _index.json                 # 存档索引文件
│   │
│   ├── world_01_幸福镇/            # 第1个世界
│   │   ├── 世界信息.json
│   │   ├── 地图.json
│   │   ├── NPC/
│   │   │   ├── 张文博/
│   │   │   │   └── 个人信息.json
│   │   │   ├── 李秀兰/
│   │   │   │   └── 个人信息.json
│   │   │   └── npc_baby_089_未命名/
│   │   │       └── 个人信息.json
│   │   ├── 动物.json
│   │   └── 世界事件日志.json       # 可选，重大事件记录
│   │
│   ├── world_02_荒野/
│   │   ├── 世界信息.json
│   │   ├── 地图.json
│   │   ├── NPC/
│   │   ├── 动物.json
│   │   └── 世界事件日志.json
│   │
│   └── ...
│
├── data/                           # 全局共享数据（所有世界共用，不随存档变化）
│   ├── libraries/                  # 欲望库、动作库、对话模板...
│   │   ├── Desires_Library.json
│   │   ├── Actions_Library.json
│   │   ├── Brains_Library.json
│   │   └── ...
│   └── config/                     # 游戏配置
│       ├── Tick时长.json
│       └── 初始NPC生成配置.json
│
└── web/                            # 代码（完全独立于存档）
```

**核心原则**：`data/` 下的文件是所有世界共用的"规则"。`saves/` 下的文件是每个世界自己的"状态"。删掉 `saves/world_02` 不会影响 `world_01`。

## 二、命名规则

### 2.1 世界 ID

```
世界ID格式: "world_" + 两位递增数字

示例: world_01, world_02, world_03, ...

规则:
  - 创建新世界时，取当前最大编号 + 1
  - 编号永远不回收——即使 world_02 被删除，下一个新世界也是 world_03
  - 目的：保证历史记录不会混乱，日志/存档不会搞混
```

### 2.2 世界文件夹名

```
格式: world_{编号}_{玩家起的名字}

示例:
  world_01_幸福镇
  world_02_荒野
  world_03_测试世界

规则:
  - 编号用于程序索引
  - 名字给人看（在世界选择界面显示）
  - 名字不能包含: \ / : * ? " < > |
  - 名字可以为空（此时文件夹名为 world_03）
```

### 2.3 NPC ID

```
NPC ID格式: "npc_" + uuid前8位

示例: npc_a3f8b2c1, npc_7d1e90ab

规则:
  - 全局唯一，跨世界不会重复
  - 使用简单的 uuid 生成器（不需要依赖外部库，自己实现8位十六进制随机串即可）
  - 同一个NPC的ID在存档前后不变
```

- 删除世界时，从此文件移除对应条目 + 删除文件夹

## 五、游戏启动流程

```
程序启动
    ↓
读取 saves/_index.json
    ↓
┌─ 文件不存在 或 世界列表为空？
│    ↓
│   显示: "没有存档，是否创造一个新世界？"
│    → [是] → 3.2 创造新世界
│    → [否] → 退出游戏
│
└─ 文件存在 且 世界列表不为空？
     ↓
     显示世界选择界面:
       ┌─────────────────────────────┐
       │  幸福镇 (第1年·春·8人)       │
       │  创建: 2026-05-25  最后: 今天 │
       │  [继续]  [删除]               │
       │                              │
       │  荒野 (第1年·春·30人)         │
       │  创建: 2026-05-26  最后: 今天 │
       │  [继续]  [删除]               │
       │                              │
       │  [创造新世界]                  │
       └─────────────────────────────┘
       
       选择 [继续] → 进入 §3.3 加载流程
       选择 [删除] → 确认弹窗 → 删除 world_XX 文件夹 + 更新 _index.json
       选择 [创造新世界] → 进入 创造新世界 流程
```

## 六、保存机制

### 6.1 保存触发时机

```
自动保存:
  - 每过一天（游戏内），自动保存一次
  - 每过一小时（现实时间），自动保存一次
  - 玩家退出时，自动保存

手动保存:
  - 玩家在菜单里选择"保存并退出"
  - 此时保存当前世界 + 更新 _index.json + 退出
```

### 6.2 保存文件列表

每次保存，更新以下文件：

| 文件 | 内容 |
|:-----|:-----|
| `saves/world_XX/世界信息.json` | 时间、Tick、天气、人口统计 |
| `saves/world_XX/地图.json` | 地形网格 + 建筑 + 火堆 + 尸体 |
| `saves/world_XX/NPC/{id}_{姓名}/个人信息.json` | 每个 NPC 的完整数据（增量：只写有变化的） |
| `saves/world_XX/动物.json` | 动物列表 |
| `saves/_index.json` | 更新"最后游玩"和"当前Tick" |

### 6.3 增量保存（性能优化）

大规模 NPC（1000+）时不需要每 Tick 全量写盘：

```
每次自动保存:
  1. 世界信息.json  → 必定更新（Tick计数变了）
  2. 地图.json       → 检查地图是否有变化（建筑/火堆/尸体），有变化才写
  3. NPC 数据        → 只写"当前Tick发生过变化的NPC"，用脏标记追踪
  4. 动物.json       → 同上，脏标记
```

## 七、切换世界 / 退出

### 7.1 退出当前世界

```
玩家选择"退出到主菜单":
  1. 保存当前世界（触发 §六 保存流程）
  2. 清空引擎内存（辨识符映射表、GOAP状态、事件总线监听）
  3. 返回到世界选择界面
```

### 7.2 切换世界

```
切换世界 = 退出当前世界 + 加载另一个世界

两个世界的所有数据完全隔离:
  - world_01 的 Tick 计数器不会影响 world_02
  - world_01 的 NPC 不会出现在 world_02
  - 辨识符映射表在切换时清空重建
```

---

## 八、删除世界

```
玩家在世界选择界面选择 [删除]:
  1. 弹出确认弹窗: "确定要删除'荒野'吗？此操作不可恢复。"
  2. 确认后:
     a. 删除 saves/world_XX/ 整个文件夹
     b. 从 saves/_index.json 的世界列表中移除对应条目
     c. 刷新世界选择界面
```

## 九、data/ 目录说明

`data/` 下的文件是**全局规则**，不随存档变化：

| 路径 | 内容 | 何时修改 |
|:-----|:-----|:---------|
| `data/libraries/*.json` | 欲望库、动作库、对话模板、大脑库、清宫表... | 只有开发者改游戏规则时才改 |
| `data/config/*.json` | Tick时长、初始NPC数量、感官半径默认值... | 同上 |
| `data/maps/*.json` | 预制地图模板（如果有） | 同上 |

**在所有世界之间，data/ 的内容完全一样。** 玩家创造世界时只复制配置参数，不复制 data/ 文件。

## 十、与现有系统的衔接

| 系统 | 衔接点 |
|:-----|:-------|
| Tick主循环 §三 初始化 | 读取 saves/ → 选择/创建世界 → 启动循环 |
| NPC创建模块 | 创建世界时调用 createInitialPopulation()，分娩时在存档目录下创建 NPC 文件夹 |
| 事件总线 | 世界切换时清空并重建监听器 |
| UI 层 | 读取 _index.json 生成世界选择界面 |
| 辨识符映射表 | 纯内存数据，加载世界时重建，切换时清空 |
