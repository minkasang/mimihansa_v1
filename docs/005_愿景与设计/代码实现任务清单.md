## 🔴 新手必读：本项目的常见踩坑（没有对话上下文也能避开）

> 如果你是新接手这个项目的 AI或开发者，以下是你最可能犯的错误。
> 这些坑都是上一轮开发中被反复验证过的——**每条后面都标了"如果犯错会怎样"。**

### 坑 1：给 NPC 贴系统标签

```
❌ 错误: npc.标签.push("[丧偶]")   // 系统告诉NPC"你丈夫死了"
❌ 错误: npc.标签.push("[孤儿]")   // 系统告诉孩子"你爸死了"

✅ 正确: NPC 只能通过 Step 2（感知）知道自己亲眼看到的事。
        配偶死了 → 她看到尸体 → 她自己的知识库更新认知。
        系统永远不直接改写 NPC 的认知数据。
```

**如果犯错**：信息壁垒崩塌。世界变成"上帝广播"，NPC 全知全能——不是涌现世界。

### 坑 2：在引擎代码里区分"这是人还是动物"

```
❌ 错误: if (entity.物种 === "狼") { 用狼的逻辑 }
❌ 错误: if (entity.物种 === "兔子") { 跳过欲望计算 }
❌ 错误: animalDesires = ["eat", "sleep"];  // 给动物硬编码欲望列表

✅ 正确: 引擎不区分人和动物。人和狼走完全相同的 GOAP 循环。
        唯一的区别是加载的 JSON 文件不同。
        人: Desires_Library.json + Actions_Library.json
        狼: Wolf_Desires_Library.json + Wolf_Actions_Library.json
        引擎只做一件事: 读JSON → 评估条件 → 执行动作。
```

**如果犯错**：新增一种动物就要改引擎代码。10种动物 = 10倍代码量 = 100倍 bug。

### 坑 3：硬编码任何数字

```
❌ 错误: if (hour >= 6 && hour <= 18)   // 白天
❌ 错误: hungerRate = 0.05              // 饥饿速度
❌ 错误: 孕期 >= 285                     // 临产触发
❌ 错误: radius = 50                     // 营地范围

✅ 正确: 所有数字都在 data/config/*.json 或 data/libraries/*.json 里。
        代码只做"读取配置 → 计算 → 写入结果"。
        想改白天范围？改 JSON，不改代码。
```

**如果犯错**：调一次参数就要改代码、重新编译、重新测试。JSON 驱动的话改一个数字就完事。

### 坑 4：违反信息壁垒——系统数据直接喂给 NPC 决策

```
❌ 错误: 欲望条件里写 { "NPC.性格.色欲": [">", 5] }
        → NPC 能读自己的性格？可以——NPC 知道自己的性格。

❌ 错误: 欲望条件里写 { "其他NPC.性格.色欲": [">", 5] }
        → NPC 能读别人的性格？绝对不行！他只能通过知识库里的"我估计的TA性格"来判断。

✅ 正确: NPC 的决策只能读:
        - 自己的数据（生理状态、性格、知识库）—— ✅
        - 世界公共数据（时间、天气、地形）—— ✅
        - 感知结果（Step 2 写入的）—— ✅
        - 别人的内部数据（性格数值、真实属性）—— ❌ 永远不能
```

**如果犯错**：NPC 做决策时能"透视"别人。恋爱系统里他能看到对方的所有性格分值——
这等于他有读心术，世界虚假。

### 坑 5：事件检测（Step 7）写 NPC 的知识库或标签

```
❌ 错误: Step 7 检测到"某某死了" → 往所有人知识库写"某某死了"
❌ 错误: Step 7 检测到"2岁了" → 往NPC标签写 [幼儿]

✅ 正确: Step 7 只做"检测系统数据变化 → 发事件到事件总线 → 结束"。
        谁该知道这个消息？——只有通过 Step 2 亲眼看到/亲耳听到的人才知道。
        Step 7 不能"通知"任何NPC。
```

**如果犯错**：死亡消息瞬间全村广播。不符合信息壁垒——而且跟口口相传机制自相矛盾。

### 坑 6：给动物写独立引擎

```
❌ 错误: class WolfEngine { ... }    // 专门给狼写一套逻辑
❌ 错误: class RabbitAI { ... }      // 专门给兔子写一套逻辑

✅ 正确: 所有生物共用一个 GOAP 引擎。
        狼和兔子的区别 = Wolf_Desires_Library.json vs Rabbit_Desires_Library.json。
        如果一只狼的行为让你觉得"引擎做不到"——不是加代码，是改 JSON。
```

**如果犯错**：代码库爆炸。每加一个物种 = 新增一个类文件。10 个物种 = 维护地狱。

### 坑 7：辨识符里混入系统 ID

```
❌ 错误: 知识库条目里写 { 辨识符:"r_001", 系统ID:"npc_qilinlin" }
        → 系统ID泄露到了NPC数据里

✅ 正确: 辨识符("r_001")是 NPC 自己世界里给一个人编的"内部代号"。
        系统ID("npc_qilinlin")只存在于引擎内存的映射表中。
        NPC 的数据文件里绝对不能出现系统ID。
```

**如果犯错**：系统数据泄露到 NPC 数据文件。将来引擎改了系统 ID 格式，所有 NPC 存档全坏。

### 坑 8：知识库和记忆库分开

```
❌ 错误: NPC 有两个数组: 知识库[] + 记忆库[]
        → 代码里要判断"这是知识还是记忆？"

✅ 正确: 只有一个 KnowledgeItem[]。
        区别用"来源"字段: "亲眼"=亲身经历、"听说"=信息传播、"习得"=技能知识。
        冲突表只追一个字段，代码只读写一个数组。
```

## 🔴 铁律：零硬编码

```
引擎代码里绝对不能出现死数字。所有"值"必须来自以下来源之一：

  来源A: JSON 配置文件（data/libraries/*.json、data/config/*.json）
  来源B: 游戏世界数据（saves/world_XX/*.json）
  来源C: NPC 自身数据（NPC.生理状态.xxx、NPC.性格.xxx 等）
  来源D: 世界状态（World.时间.xxx、World.grid 等）

❌ 禁止:
  if (hour >= 6 && hour <= 18) { ... }     → 硬编码白天
  if (npc.标签.includes("婴儿")) { ... }   → 硬编码标签匹配
  if (species === "狼") { 攻击力 = 7 }     → 硬编码物种属性
  rate = 0.05                               → 硬编码变化率
  distance = 50                             → 硬编码距离

✅ 正确:
  白天判定 → 读 data/config/时间配置.json 中的 白天开始/结束 字段
  婴儿本能 → 读 data/config/本能触发配置.json 中的 饥饿阈值
  狼攻击力 → 读 data/libraries/Animals_Library.json 中对应物种的 力量 字段
  变化率 → 读 data/config/生理速率配置.json 中的 口渴增速
  距离 → 读 data/libraries/Animals_Library.json 中对应物种的 感知.视觉半径
```

## 🔴 执行铁律：验证失败怎么办

```
每个步骤都有验证标准。验证不通过的处理方式：

  1. 验证失败 → 修复该步骤中的代码（不跳到下一步）
  2. 连续3次修复仍失败 → 回滚本阶段所有改动 → 标记 [阻塞] → 报告原因
  3. 任何阶段完成后 → 必须跑一次完整 Tick 循环（≥86400 Tick）确保不崩溃
  4. 如果改动影响了旧功能 → 旧功能验证必须同步通过（不能新功能通了旧功能坏了）
```
