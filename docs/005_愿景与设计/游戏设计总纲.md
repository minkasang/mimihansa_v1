# 游戏设计总纲

> 本文档是 `005_愿景与设计` 目录的**入口总结**——用一页纸说清「我们在做什么、最大特点是什么」。
> 细节规范请查阅本目录下的各专题文档；本文不重复展开机制细节。
> ⚠️ 愿景级文档，描述设计意图与核心原则，不直接映射当前代码实现状态。

---

## 一、一句话定义

**像素风的涌现式人生沙盒**：100+ NPC 在参考现实世界骨架的简化规则中自主生活——从原始求生演进到农业、贸易、婚恋、村落治理；玩家可旁观世界演化，也可投角色入世界搅动格局。**不靠剧本，靠规则碰撞出人生。**

---

## 二、这是什么 / 不是什么

| 是 | 不是 |
|:---|:-----|
| 涌现式模拟：同样 NPC 跑 100 遍，跑出 100 种人生 | 剧情驱动 RPG，给 NPC 写死命运线 |
| 参考现实骨架，剥离不必要细节 | 1:1 复制现实世界每个微观环节 |
| 效用 AI + 数据驱动（JSON 库配置行为） | LLM 全程接管每个 NPC 的决策 |
| 完整人生 + 文明纵向演进（出生→死亡，石器→村政） | 只做战斗/只做建造/只做社交的单一玩法 |
| 观察者 + 参与者两种玩法 | 必须操控主角才能玩的传统游戏 |

**对标参照**（帮助理解，非抄袭目标）：《边缘世界》的俯视生存建造感 + 《斯坦福小镇》的社会仿真深度，但野心覆盖**更长的时间跨度**和**更完整的社会系统**。

## 三、五大核心特点

### 特点 1：编织「可能性」，不写「剧本」

我们的角色是**规则制定者 + 模板提供者**，不是编剧：

```
NPC 的选择 = 性格底色 × 生活经历 × 当前环境 × 随机扰动
```

- 写规则（公式、判定流程）→ NPC 在里面自由决策
- 提供模板（欲望库、动作库、对话模板）→ NPC 在里面自由组合
- NPC 选 A 还是选 B，是**涌现**出来的，不是我们写死的

**验证标准**：禁止给任何 NPC 写死命运线（「他一定会娶她」「他一定会当恶霸」）。

→ 详见：`.trae/agents/规范澄清.md` §8.5

---

### 特点 2：信息壁垒——NPC 活在「认知」里，不是「全知」里

**系统数据和 NPC 认知是两个世界，绝对不能串通。** 这是本项目与多数上帝视角模拟器最大的区别。

| NPC 可以知道 | NPC 不能知道 |
|:------------|:------------|
| 亲眼看到的事物 | 系统里的房产归属、人口统计 |
| 亲耳听到的话 | 「张文博死了」这类系统广播 |
| 自己亲身经历的事 | 感知范围外发生的任何事 |

- 「孤儿」不是客观系统标签，而是**个体认知**——孩子不知道父亲死了，就不觉得自己是孤儿
- 信息有滞后、有失真：A 今天知道 B 有手机，B 明天换了新手机，A 不知道
- 这条规则**高于**任何性能优化和便捷设计

→ 详见：`感知与信息传播系统.md`

---

### 特点 3：有「人性弱点」的 NPC，不是理性机器

NPC 的行为建模追求**像真人一样不完美**：

- **懒惰与拖延**：知道该做但不想做，拖到最后才动，甚至一直不做（麻木）
- **欲望与克制**：心里想要新衣服，但权衡后不买（觉得不值/没钱）
- **攀比心**：看到邻居盖了大楼，自己也想盖
- **记仇与背叛**：伤害会被记住，关系可能永久破裂
- **认知偏差**：道听途说、谣言、误解，影响后续决策

34 维性格 + 弹性性格系统驱动这些决策；引擎只负责算分，不负责替 NPC 「做正确选择」。

→ 详见：`世界能发生什么.md` §九、`NPC参数总表.md`

---

### 特点 4：完整人生 + 文明演进的纵向深度

世界不是静态背景板，而是**随 NPC 行为自然演化**的时间线：

```
原始生存          农业与季节          社会与经济           治理与文明
找水→觅食→生火    种田→储藏→过冬     择业→交易→产业链     选举→税收→纠纷调解
制作→搭庇护所     钓鱼→农具→纺织     恋爱→结婚→生育       帮派→村政过渡
道路→村庄形成     冲突→耐久→同居     借贷→跨区域贸易      教育→文化积累
```

**人生阶段**同样完整：受孕遗传 → 童年教育 → 青少年探索 → 成年婚恋职业 → 中年惰性 → 老年传承 → 死亡遗产。

→ 详见：`世界能发生什么.md`（全景框架）、各专题系统设计文档

---

### 特点 5：一套引擎跑所有人生——数据驱动，业务无关

引擎**不区分业务**。「想吃饭」和「想恋爱」对引擎来说只是：一条欲望 JSON + 条件 + 效果。

```
感知 → 欲望筛查 → 效用打分 → GOAP 规划 → 执行指令 → 效果结算
         ↑                                              ↓
    Desires_Library                              效果路由表
    Actions_Library                              参数变更 / 事件产生
    Brains_Library（34维性格打分）
```

- 新增一种行为 ≈ 新增 JSON 配置，不必改引擎核心
- 所有领域系统（吃饭/工作/打架/传播信息）挂同一框架
- 规范与代码必须双向映射，字段名中文、变量名英文

→ 详见：`引擎架构.md`、`效果路由表.md`、`Tick主循环.md`

## 四、设计哲学三条

### 4.1 参考现实，但只留骨架

本项目的本质是**建立一个参考现实世界的游戏世界**，服务于游戏运行，而非复制现实每个细节。

> 例：现实中排卵日受 50+ 因素影响 → 游戏里简化为 5 个因素，其余坍缩为随机扰动。

### 4.2 设计必须落到程序层

所有机制描述必须能翻译成代码——公式、条件表达式、数据结构、判定流程。「大概」「可能」「应该」不是合格的设计语言。初始值可以拍脑袋，标注「待调优」即可，但不能没有可执行的规格。

### 4.3 兼容现有架构，最小侵入

新机制优先找「加一条 JSON 就能实现」的路径；需要推翻底层模块的方向，除非用户明确要求重构，否则放弃或找轻量替代。

## 五、玩家体验

### 玩法 A：观察者模式

- 不创建角色，以上帝视角观看世界演化
- 点击任意 NPC 查看完整履历：性格、经历、关系网、一生轨迹
- 类似「上帝数据面板」——看百年兴衰，看涌现出的故事

### 玩法 B：创建者模式

- 创建一个 NPC 投入世界
- 可能统治（拉帮结派、当镇长）、被统治、或当普通人
- 玩家角色有寿命限制；未来可通过特殊机制（如「修仙」）延长寿命，持续观察世界
- 做好人/坏人/普通人，都会影响世界走向

→ 详见：`世界能发生什么.md` §八

## 六、技术路线概要

| 维度 | 选择 |
|:-----|:-----|
| 渲染 | 像素风，HTML5 Canvas，32px/格 |
| 语言 | TypeScript（Vite 构建，`web/map-demo/`） |
| AI 决策 | 效用 AI + GOAP，100+ NPC 纯代码驱动 |
| LLM | 仅在特定场景接管，非核心路径 |
| 数据 | JSON 库驱动（欲望/动作/性格/对话/建筑…） |
| 架构 | MVC，逻辑与表现分离，支持未来迁移 Unity/Godot |

## 七、当前阶段目标

**近期里程碑**：让一个最小村落（约 30–40 个 NPC）**从原始生存跑满 1 年**。

```
第一阶段 ✅  原始生存（找水/觅食/生火/制作/村庄形成）
第二阶段 ✅  农耕与季节（种田/储藏/过冬/钓鱼）
第三阶段 ✅  社会雏形（冲突/耐久/同居/村政过渡）
第四阶段 🔄  设计→代码落地（引擎子目标链、效果路由、欲望库补全…）
```

设计文档（本目录 24+ 份）已覆盖 Demo 闭环所需系统；当前主要工作是**把愿景翻译成可运行代码**，断裂点清单见 `Kimi_核心缺失环节清单.md`。
