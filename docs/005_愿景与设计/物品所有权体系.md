﻿﻿﻿﻿# 物品所有权体系

> ⚠️ 规范研究文档。定义游戏中每个物品的唯一编码、所有权归属、以及 NPC 如何知道"这个东西是谁的"。

---

## 一、最小单位：物平唯一 ID

游戏世界里的每一样东西都必须有一个独一无二的 ID。这是为了防止两个 NPC 同时"拥有"同一块石头而搞混。

### 1.1 ID 格式

```
物品ID格式: "item_" + uuid 前8位

示例: item_a3f8b2c1, item_7d1e90ab

规则:
  - 每个物品实例都有唯一 ID，即使两块石头看起来一模一样
  - NPC ID 跨世界唯一（uuid），物品 ID 同样跨世界唯一
```

### 1.2 什么算"一个物品"（最小单位）

| 物品类型 | 一个单位 | 可堆叠？ | 示例 |
|:---------|:---------|:--------:|:-----|
| 固体物品 | 一块石头、一把刀、一件衣服 | 不可堆叠（每个有独立ID） | 石头01, 石头02... 即使外观一样 |
| 可堆叠消耗品 | 一份野果、一块肉 | 可堆叠（同类型可叠放） | 3个野果 = 一个条目，数量=3 |
| 连续物质（水） | 一捧水（最小取水单位） | 可堆叠到容器容量上限 | 1桶水 = 100捧水 |
| 容器 | 一个木桶/陶罐 | 不可堆叠 | 空桶 vs 满桶是两个状态 |

### 1.3 物品数据结构

```typescript
interface Item {
  id: string;                  // "item_a3f8b2c1"（全局唯一）
  名称: string;                // "石头"、"木棍"、"石刀"、"一捧水"
  类型: string;                // "原料" | "工具" | "食物" | "容器" | "建材" | "饮水"
  数量: number;                // 同类堆叠数量（不可堆叠物品始终=1）
  所有者ID: string | null;     // ← 谁拥有它。null=无主（在地上/野外）
  位置: [number, number] | null; // 在地上的位置。如果在物品栏里则为null
  容器ID?: string;             // 水装在桶里 → 桶的ID
  物品栏所在NPC?: string | null; // 在谁的背包里
  质量?: number;               // 1~10，影响效果和使用寿命
  变质时间?: number;           // Tick数，食物类过期时间
  标签: string[];              // ["锋利的"]、["新鲜的"]、["黄志远标记过的"]
}
```

## 二、所有权：这个东西是谁的

### 2.1 NPC 怎样知道东西是自己的

NPC 自己捡起来 → 物品的所有者ID 被引擎写入 npc.id。NPC 的认知里"这个东西是我的"，因为他在 Step 5（行动）里亲自捡起来的。

```
Step 5 行动执行（NPC 捡东西）:
  NPC 移动到物品旁边 → 执行"捡起"动作
  → item.所有者ID = npc.id
  → item.位置 = null（从地图上移除）
  → item.物品栏所在NPC = npc.id
  → npc.物品栏.push(item)
  
  ← NPC 自己的行动 → 自己知道 → 符合信息壁垒（亲身经历）
```

### 2.2 NPC 怎样知道东西是别人的

```
情形A: 看到有人使用某个工具
  Step 2 (感知): 看到黄志远拿着石刀在砍树
  → 知识库: { 内容:"黄志远手里那把石刀", 类型:"事实", 来源:"亲眼" }
  → 我推断: 那把刀是黄志远的

情形B: 看到地上有个物品，旁边有"主人的痕迹"
  Step 2: 看到树下有一块石头，旁边是陈德厚常用的休息点
  → 知识库: { 内容:"树下有块石头，可能是陈德厚的", 可信度:0.6, 来源:"亲眼" }

情形C: 直接问
  Step 6 (社交): "这石头是你的吗？"
  → 对方回答: "不是，是周明哲的"
  → 知识库: { 内容:"树下的石头是周明哲的", 来源:"亲耳", 可信度:0.9 }

情形D: 偷东西
  有人趁人不注意把东西拿走了
  → 原主人: 知识库里还是"那块石头是我的"
  → 原主人下次去看: 石头没了
  → 知识库更新: { 内容:"我的石头不见了", 来源:"亲身" }
  → 他可能怀疑某人偷了 → 但这只是他的认知，不一定是真的
```

### 2.3 遗产转移时的所有权

```
NPC死亡 → 事件总线回调执行遗产结算（死亡系统 §3.2）:
  物品栏 传递给继承人集团
  → item.所有者ID = 继承人.id
  → item.物品栏所在NPC = 继承人.id
  → 继承人.物品栏.push(item)

  继承人自己知道: "这些是新东西"（亲身经历——东西到自己手里了）
  其他人: 不知道物品转移了（除非看到或听说了）
  如果有人看到继承人用死者的刀 → 可能推断"这是继承的刀"
```

## 三、水：连续物质的特殊处理

### 3.1 水的最小单位

```
1 捧水 = 最小取水单位（用手捧起来喝）
1 容器.容量 = N 捧水（如: 木碗=10捧, 陶罐=100捧, 水袋=30捧）

喝水时: 消耗 1 捧水 → 口渴度 -5
装在容器里: 按容器容量显示 "满桶水 (100/100捧)"
```

### 3.2 水需要唯一 ID 吗？

```
水源（河流/湖泊）: 不需要 ID。水源是无限的地形特征
  → NPC 走到河边 → 执行"喝水" → 口渴度 -5（直接喝，不生成物品实体）

装了水之后: 水成为容器的一部分，不是独立物品
  → 容器有独立 ID
  → 内容物（水）按 数量 存储
  
只有在特殊情况下才给"水量"赋予独立 ID:
  比如: 下雨接了一罐雨水，这罐水作为一个物品实体有独立ID
  但水本身没有ID——它只是容器的一个属性
```

## 四、物品丢失、被偷、赠与

### 4.1 物品丢失

```
NPC 主动丢弃:
  → item.所有者ID = null
  → item.位置 = 当前位置
  → item.物品栏所在NPC = null
  NP C自己知道: "我扔掉了"
  别人: 只能通过 Step 2 感知到地上多了个东西

物品被遗忘（NPC移动后物品留在地上）:
  同上
```

### 4.2 赠与

```
NPC A 把石刀赠给 NPC B:
  Step 6 (社交): A 说"这把刀送给你"
  → A 执行"交出物品"动作: A.物品栏.remove(石刀)
  → B 执行"接收物品"动作: B.物品栏.add(石刀)
  → item.所有者ID = B.id
  
  双方知识库更新:
    A: 刀送出去了（亲身经历）
    B: 收到了礼物（亲身经历）
```

## 五、与现有系统的衔接

| 系统 | 衔接点 |
|:-----|:-------|
| 效果路由表 | "生成实体"效果中引用物品ID |
| 死亡系统 §3.2 | 遗产转移时更新物品.所有者ID |
| 感知系统 | Step 2 感知到物品 → 可推断所有者 |
| 市场结算 | 交易时物品所有权转移 |
