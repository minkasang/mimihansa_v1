# Tick系统I/O注册表

> 运行时契约文档。每个挂载在Tick循环中的系统，声明自己的读/写权限。
> ⚠️ 任何新增的Tick步骤必须先在本表注册——防止两个系统抢写同一字段。

---

## 一、注册格式

```
系统名称
  挂载步骤: Tick主循环的第几步
  读取数据: [哪些参数/字段/表]    ← 只读
  写入数据: [哪些参数/字段/表]    ← 会修改
  产生事件: [是否产生可被其他步骤感知的变化]
  依赖: [必须在哪些步骤之后执行]
```

## 三、写入冲突检查

| 字段 | 写入的步骤 | 冲突？ |
|:-----|:---------|:------|
| NPC.生理状态.* | 步骤3, 步骤5 | ✅ 有冲突：如果NPC同时在做动作且生理推演改了同字段(如体力)，以步骤5动作为准(后执行覆盖) |
| NPC.生理状态.母乳值 | 步骤3, 步骤5 | ⚠️ 步骤3每Tick维护（产后产奶），步骤5执行喂奶时-20。解决方案：步骤5优先——如果步骤5已扣→步骤3本次跳过累加 |
| NPC.知识库 | 步骤2, 步骤6, 步骤7(信息传播) | ⚠️ 多步写入——步骤2写感知结果、步骤6写关系事件、步骤7(信息传播)写入新知识条目。解决方案：知识库为追加式（append-only），各步骤只新增条目不修改已有条目，通过唯一id去重。 |
| NPC.好感度 | 步骤6 | 独写 ✅ |
| NPC.位置 | 步骤5 | 独写 ✅ |
| NPC.物品栏 | 步骤5, 步骤8 | ✅ 有冲突——行动执行和市场结算可能同时改物品栏。解决方案：步骤8每天执行一次，步骤5也是按天规划，不会同一天抢同物品(除非同一NPC在步骤5买一件商品、同一Tick在步骤8又结算出售同一件商品——概率极低但需加锁) |
| NPC.标签 | 步骤3, 步骤5, 步骤6, NPCFactory | ⚠️ 多源写入——步骤3写[临产]/[分娩中]/[哺乳期]等生理状态标签，步骤5通过行动效果写标签，步骤6社交写入关系标签，NPCFactory创建婴儿时写[婴儿]。解决方案：标签按维度划分（生理/关系/行为），各不重叠。 |
| World.grid[].状态 | 步骤5 | 独写 ✅ |
| 动物.位置 | 步骤2.5 | 独写 ✅ |
| 婴儿.听觉事件 | 步骤3.5 | 独写 ✅（只有本能反应产生哭声事件） |

**需要加锁的唯一情况**：NPC在同一Tick执行一个动作(步骤5)且同时触发市场结算(步骤8)且两者涉及同一物品——加上 `if (物品已被转移) return` 的幂等检查即可。

## 四、新增系统的注册流程

```
1. 决定挂载在哪一步(或新建一步)
2. 声明读取哪些字段(只读)
3. 声明写入哪些字段(检查本表确保没有其他步骤写同一个字段)
4. 如有冲突→协商解决(改步骤顺序/加锁/拆分字段)
5. 在本表登记
```
