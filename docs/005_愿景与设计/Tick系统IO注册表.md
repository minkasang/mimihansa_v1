# Tick系统I/O注册表

> 运行时契约文档。每个挂载在Tick循环中的系统，声明自己的读/写权限。
> ⚠️ 任何新增的Tick步骤必须先在本表注册——防止两个系统抢写同一字段。

---

## 一、注册格式

```
系统名称
  挂载步骤: Tick主循环的第几步
  读取数据: [哪些参数/字段/表]    ← 只读
  写入数据: [哪些参数/字段/表]    ← 会修改
  产生事件: [是否产生可被其他步骤感知的变化]
  依赖: [必须在哪些步骤之后执行]
```

## 二、已注册系统

### 1. 时间推进
```
挂载步骤: 1
读取数据: World.时间
写入数据: Tick计数器, 日期, 天气状态
产生事件: 日期变更、季节切换
依赖: 无
```

### 2. 环境感知
```
挂载步骤: 2
读取数据: NPC当前位置, World.grid, 其他实体的坐标/标签
写入数据: NPC.感知结果(视觉/听觉/嗅觉), NPC.知识库
产生事件: 感知到新实体/事件
依赖: 步骤1(需要更新后的世界状态)
```

### 3. 生理状态推演
```
挂载步骤: 3
读取数据: NPC.生理状态, NPC.怀孕状态, NPC.周期
写入数据: 饥饿度, 口渴度, 疲劳度, 精力, 开心值, 健康值(生病中), 性欲值,
          孕期天数, 当前周期日
产生事件: 饥饿>=8 → [饥饿风险], 口渴度>=10 → [脱水风险],
          孕期天数>=300 → 分娩
依赖: 步骤1(需要日期推进)
⚠️ 注意: 写入开心值时不要与步骤6(关系)同时写入——关系步骤只读
```

### 4. 欲望计算
```
挂载步骤: 4
读取数据: NPC.生理状态, NPC.性格, NPC.物品栏, NPC.感知结果, World.时间
写入数据: NPC.当前目标, NPC.当前欲望
产生事件: —
依赖: 步骤2, 步骤3(需要最新的生理状态+感知)
```

### 5. 行动执行
```
挂载步骤: 5
读取数据: NPC.当前目标, NPC.位置, NPC.体力, World.grid
写入数据: NPC.位置, NPC.体力, NPC.物品栏, NPC.生理状态, World.grid[].状态,
          World.fire[].燃料, World.buildings[]
产生事件: 移动/建造/攻击/交易等外部可视事件
依赖: 步骤4(需要欲望决策结果)
⚠️ 写入范围最广——几乎可以改任何东西。所有子模块指令(cmd_xxx)的写入都在此步。
```

### 6. 关系与社交网络
```
挂载步骤: 6
读取数据: NPC.社会关系.好感度, NPC.感知结果, NPC.性格
写入数据: NPC.社会关系.好感度, NPC.记忆库
产生事件: 好感度骤变→可能触发冲突/恋爱
依赖: 步骤2(需要感知到附近有谁才能互动)
```

### 7. 信息传播
```
挂载步骤: 6(并行，社交步骤内执行)
读取数据: NPC.知识库, NPC.感知结果(听觉)
写入数据: NPC.知识库, NPC.记忆库
产生事件: —
依赖: 步骤2
```

### 8. 事件检测
```
挂载步骤: 7
读取数据: NPC.生理状态, World.时间, NPC.年龄, NPC.怀孕状态, NPC.标签
写入数据: NPC.标签, NPC.记忆库
产生事件: 出生、死亡、学龄触发、就业年龄、流产判定
依赖: 步骤3(需要最新的生理数据)
⚠️ 此步骤写入"标签"—其他系统不要同时写入相同标签
```

### 9. 市场结算
```
挂载步骤: 8
读取数据: 店铺.库存, 店铺.成本, NPC.性格(商人), World.时间
写入数据: 店铺.定价, NPC.金钱(交易双方), NPC.物品栏
产生事件: 价格变动、交易记录
依赖: 步骤1(每天只执行一次)
```

### 10. 动物推进
```
挂载步骤: 2.5(在环境感知和生理推演之间)
读取数据: Animal.生理状态, Animal.位置, World.grid
写入数据: Animal.生理状态, Animal.位置
产生事件: 动物繁殖、动物死亡、狼群攻击
依赖: 步骤2
```

### 11. 清理任务
```
挂载步骤: 9
读取数据: —
写入数据: World.尸体[](过期删除), World.临时事件[](过期清理)
产生事件: —
依赖: 步骤7(需要处理完死亡事件)
```

## 三、写入冲突检查

| 字段 | 写入的步骤 | 冲突？ |
|:-----|:---------|:------|
| NPC.生理状态.* | 步骤3, 步骤5 | ✅ 有冲突：如果NPC同时在做动作且生理推演改了同字段(如体力)，以步骤5动作为准(后执行覆盖) |
| NPC.标签 | 步骤7 | 独写 ✅ |
| NPC.知识库 | 步骤2, 步骤7 | ✅ 有冲突——步骤2写感知结果，步骤7可能同时写事件标签。解决方案：步骤7只新增知识条目，不修改已有条目 |
| NPC.好感度 | 步骤6 | 独写 ✅ |
| NPC.位置 | 步骤5 | 独写 ✅ |
| NPC.物品栏 | 步骤5, 步骤8 | ✅ 有冲突——行动执行和市场结算可能同时改物品栏。解决方案：步骤8每天执行一次，步骤5也是按天规划，不会同一天抢同物品(除非同一NPC在步骤5买一件商品、同一Tick在步骤8又结算出售同一件商品——概率极低但需加锁) |
| World.grid[].状态 | 步骤5 | 独写 ✅ |
| 动物.位置 | 步骤2.5 | 独写 ✅ |

**需要加锁的唯一情况**：NPC在同一Tick执行一个动作(步骤5)且同时触发市场结算(步骤8)且两者涉及同一物品——加上 `if (物品已被转移) return` 的幂等检查即可。

## 四、新增系统的注册流程

```
1. 决定挂载在哪一步(或新建一步)
2. 声明读取哪些字段(只读)
3. 声明写入哪些字段(检查本表确保没有其他步骤写同一个字段)
4. 如有冲突→协商解决(改步骤顺序/加锁/拆分字段)
5. 在本表登记
```
