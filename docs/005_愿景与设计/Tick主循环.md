## 零、Tick定义

```
1 Tick = 游戏内 1秒
配置：data/config/Tick时长.json

实际运行中：
  引擎以固定频率运行（例如每秒10Tick）
  但UI渲染可以按显示器刷新率（60fps）独立运行
  两者解耦——逻辑走的Tick，渲染走的帧
```

## 一、每Tick执行顺序

```
每个Tick按以下顺序依次执行，保证系统不会互相踩脚：

1. 时间推进
   1.1 Tick计数器 +1
   1.2 日期推进（小时/天/月/年）
   1.3 天气更新（阳光/下雨/刮风……）
   1.4 事件日历更新（今天是什么重要日子吗？）

2. 环境感知
   2.1 每个NPC的第二眼、耳边、鼻前——更新PerceptionResult[]
   2.2 把感知到的信息写入各自的知识库

3. 生理状态推演
   3.1 所有NPC：
      - 饥饿度 + 基础值（每N个Tick加1）
      - 疲劳度 + 基础值
      - 精力：自动回复（休息时）+2、活跃时-1
      - 开心值：缓慢衰减
      - 健康值：生病中每秒-0.1
   3.2 怀孕NPC：孕期天数+1
   3.3 女性NPC：经期日推进（见出生系统 §3.2）

4. 欲望计算
   4.1 每个NPC依次执行DesireEvaluator：
       - 遍历所有的欲望库（Desires_Library.json）
       - 对每条欲望评估触发条件
       - 计算效用分
       - 选出得分最高的欲望
   4.2 创建相应目标 → 弹出GOAP计划
   4.3 如果某个欲望的得分超过当前动作→产生打断

5. 行动执行
   5.1 每个NPC执行当前GOAP计划的第一步
       - GOAPPlanner把目标拆解为指令序列
       - 指令序列通过ModuleRegistry执行
         · cmd_移动 [方向/距离]
         · cmd_说话 [内容]
         · cmd_交互 [目标]
         · cmd_建造 [配方]
         · ……（见指令模块库）
   5.2 如果指令序列执行完了→目标完成→换下一个目标

6. 关系与社交网络更新
   6.1 每2小时一次（不必每Tick）：
       - 熟悉度衰减：长期不见面的人好感微降
       - 朋友状态更新
   6.2 信息传播（聊天）
       - 同听觉范围内的NPC随机配对聊天
       - 双方互相交换一条知识

7. 事件检测
   7.1 生成检测：
       - 是否有人触发流产？（出生系统 §五）
       - 是否有人到学龄了？（童年 §三）
       - 是否有人到就业年龄了？（职业 §2.3）
   7.2 死亡检测：
       - 年龄 >= 实际寿命？（死亡系统 §2.1）
       - 饥饿度 = 10 持续N天？（死亡系统 §2.2）
       - 健康值 <= 0？（死亡系统 §2.3）
       - 处理尸体和遗产（死亡系统 §三）
   7.3 新生检测：
       - 孕期天数 >= 300天 → 分娩
       - 多胞胎判定（出生系统 §十一）

8. 市场与产业结算（每天只执行一次）
   8.1 价格更新（定价日到了吗？）
   8.2 商人计算成本+利润+重新定价
   8.3 库存移动（NPC购买→商品转移）
   8.4 生产（作坊生产出新商品）
   8.5 雇佣/裁员决算

9. 清理任务
   9.1 删除缓存的过时感知数据
   9.2 更新统计数据（怪物计数器、死亡计数器）
   9.3 日志写入（如果需要的话）
```

## 二、性能优化

### 2.1 哪些可以降频

| 步骤 | 是否每Tick | 降频策略 |
|:-----|:---------:|:---------|
| 时间推进 | ✅ 每Tick | — |
| 环境感知 | ✅ 每Tick | NPC只有在移动时才重新更新 |
| 生理状态 | ✅ 每Tick | — |
| 欲望计算 | 每10 Tick | 不需要每一秒都想 |
| 行动执行 | ✅ 每Tick | — |
| 关系更新 | 每2小时 | 不需要太频繁 |
| 信息传播(聊天) | 每5 Tick | 随机配对 |
| 事件检测 | 每Tick | — |
| 市场结算 | 每天一次 | 价格等不会每秒变化 |
| 死亡检测 | 每Tick | — |

### 2.2 大规模NPC的调度

```
如果NPC数量上到1000+：
  欲望计算 → 队列化处理（每Tick只算一小部分）
  每个NPC每Tick实际上只执行1~2个"动作单元"
  大部分NPC处于"空闲"状态，不需要全量计算
```

## 三、初始化流程（游戏启动）

```
游戏启动时执行一次：

1. 地图生成/加载
   → 读 data/maps/幸福镇.json → 生成100×100网格
   → 生成地形图层

2. NPC生成
   → 读 data/config/初始NPC生成配置.json
   → 随机生成第一代村民(8~12人)
   → 载入他们的个人数据

3. 初始欲望触发
   → 每个NPC运行第一次欲望计算
   → 第一个欲望就能拿到 → 第一个动作就开始执行

4. Tick循环启动
   → 每隔1/10秒调用一次tick()
```

## 四、每Tick的时间用图（性能预算）

```
假设100个NPC，目标每Tick耗时 < 10ms：

  时间推进         →  <0.1ms（纯计数器）
  环境感知         →  <1ms   (距离计算)
  生理状态         →  <1ms   (简单的加减)
  欲望计算×20%  →  <3ms   (效用打分)
  行动执行         →  <3ms   (路径+指令)
  关系社交         →  每2小时执行
  市场结算         →  每天执行
  事件检测         →  <1ms
  渲染(独立于逻辑) →  由GPU处理
  
总预算：约8ms << 16ms（60fps）
```
