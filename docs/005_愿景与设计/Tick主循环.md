## 零、Tick定义

```
1 Tick = 游戏内 1秒
配置：data/config/Tick时长.json

实际运行中：
  引擎以固定频率运行（例如每秒10Tick）
  但UI渲染可以按显示器刷新率（60fps）独立运行
  两者解耦——逻辑走的Tick，渲染走的帧
```

## 一、每Tick执行顺序

> ⚠️ 本表是 Tick 主循环的唯一权威定义。每步骤的详细读写权限声明见 `Tick系统IO注册表.md`。
> 本表与 IO 注册表必须保持同步——IO 注册表的每个已注册系统必须在本表中能找到对应步骤。

```
每个Tick按以下顺序依次执行（共12步）：

1. 时间推进 ← TimeSystem.ts
   1.1 Tick计数器 +1
   1.2 计算当前秒/分/时/日/月/年/季节/是否白天
   1.3 天气更新（阳光/下雨/刮风……）
   1.4 事件日历更新（今天是什么重要日子吗？）

2. 环境感知 + 辨识符匹配
   2.1 每个NPC的眼、耳、鼻——更新PerceptionResult[]
   2.2 辨别符匹配：感知到的实体 → 引擎内存查映射表 → 
       新实体：生成辨识符 + 创建知识库人物条目
       旧实体：匹配已有辨识符 + 更新知识库见面记录
   2.3 把感知到的信息写入各自的知识库

2.5 动物推进
    - Animal.生理状态自然变化（饥饿+1、疲劳+1...）
    - Animal.位置更新（随机移动/迁移/觅食）
    - 动物繁殖判定、死亡判定
    - ⚠️ v3.1 狩猎时序：动物在检测到威胁时执行逃跑（Step 2.5），
      但如果NPC已在3格冲刺范围内 → 猎人Step 5先于动物反应执行
    - 狼群嚎叫检测 → 产生听觉事件

3. 生理状态推演 + 分娩状态机
   3.1 所有NPC：
      - 饥饿度 + 基础值（每N个Tick加1）
      - 口渴度 + 基础值
      - 疲劳度 + 基础值
      - 精力：自动回复（休息时）+2、活跃时-1
      - 开心值：缓慢衰减
      - 健康值：生病中每秒-0.1
   3.2 怀孕NPC：孕期天数+1
   3.3 女性NPC：经期日推进（见出生系统 §3.2）
   3.4 哺乳期NPC：母乳值维护（产后产奶）
   3.5 分娩状态检测：
      - 孕期天数 >= 285 → 触发临产流程（出生系统 §十三）
      - 临产中 → 维持分娩状态
      - 分娩完成 → 调用NPCFactory.createChild() + 产后状态结算

3.5 本能反应（仅 [婴儿] 标签NPC）
    - ⚠️ v3.0 修正：婴儿不跳过 Step 2 和 Step 3——他有眼睛有耳朵
      他只是不做 GOAP 决策（跳过 Step 4 和 Step 5）
    - 饥饿度>5 → 执行: 哭（产生听觉事件，半径40格）
    - 疲劳度>7 → 执行: 睡
    - 身体不适 → 执行: 哭
    - 默认 → 安静/睡觉
    - ⚠️ 不走GOAP，跳过步骤4和5。

4. 欲望计算 + 生存欲望
   4.1 跳过标签包含 [婴儿] 的NPC
   4.2 每个NPC依次执行DesireEvaluator：
       - [幼儿] → 加载幼儿欲望库（5-8条）
       - [学龄]+ → 加载完整欲望库
       - 遍历欲望库，评估触发条件
       - 计算效用分
       - 选出得分最高的欲望
   4.3 创建相应目标 → GOAPPlanner拆解为指令序列
   4.4 如果新欲望得分超过当前动作 → 打断当前目标

5. 行动执行 + 生存动作
   5.1 跳过标签包含 [婴儿] 的NPC
   5.2 每个NPC执行当前GOAP计划的第一步
       - GOAPPlanner把目标拆解为指令序列
       - 指令序列通过ModuleRegistry执行
         · cmd_移动 [方向/距离]
         · cmd_说话 [内容]
         · cmd_交互 [目标]
         · cmd_建造 [配方]
         · action_feed_baby, action_drink, action_forage, ...
         · ……（见指令模块库）
   5.3 如果指令序列执行完了 → 目标完成 → 换下一个目标

6. 关系与社交网络更新 + 信息传播
   6.1 每2小时一次（不必每Tick）：
       - 熟悉度衰减：长期不见面的人好感微降
       - 朋友状态更新
   6.2 信息传播（聊天）——每5 Tick，随机配对：
       - 同听觉范围内的NPC随机配对聊天
       - 双方互相交换一条知识

7. 事件检测
   7.1 生成检测：
       - 是否有人触发流产？（出生系统 §五）
       - 是否有人到学龄了？（童年 §三）
       - 是否有人到就业年龄了？（职业 §2.3）
       - 年龄达到标签切换节点？
         2岁: [婴儿]→[幼儿], 6岁: [幼儿]→[学龄]
         13岁: [学龄]→[青少年], 18岁: [青少年]→[成年]
   7.2 死亡检测：
       - 年龄 >= 实际寿命？（死亡系统 §2.1）
       - 饥饿度 = 10 持续N天？（死亡系统 §2.2）
       - 健康值 <= 0？（死亡系统 §2.3）
       - 处理尸体和遗产（死亡系统 §三）
   7.3 ⚠️ 只检测系统数据变化、写入知识库。不修改NPC标签（标签由感知/行动/社交步骤写入）

7.5 事件总线分发
   - 收集本Tick所有已触发事件
   - 分发给监听者（引擎内部模块回调）
   - 事件示例：
     · "分娩完成" → NPCFactory.createChild()
     · "NPC死亡" → 人口计数-1、财产继承权变更、工作空缺通知
     · "建筑完工" → 世界建筑物列表更新
   - ⚠️ 事件总线只管引擎内部模块通信，不直接碰NPC认知数据

8. 市场与产业结算（每天只执行一次）
   8.1 价格更新（定价日到了吗？）
   8.2 商人计算成本+利润+重新定价
   8.3 库存移动（NPC购买→商品转移）
   8.4 生产（作坊生产出新商品）
   8.5 雇佣/裁员决算

9. 清理任务
   9.1 删除缓存的过时感知数据
   9.2 更新统计数据（怪物计数器、死亡计数器）
   9.3 过期尸体删除、过期临时事件清理
   9.4 日志写入（如果需要的话）
```

## 二、性能优化

### 2.1 哪些可以降频

| 步骤 | 是否每Tick | 降频策略 |
|:-----|:---------:|:---------|
| 1. 时间推进 | ✅ 每Tick | — |
| 2. 环境感知+辨识符 | ✅ 每Tick | NPC静止时不需要全量重算 |
| 2.5 动物推进 | ✅ 每Tick | 动物数量稳定，开销可控 |
| 3. 生理推演+分娩 | ✅ 每Tick | 纯加减法，极轻 |
| 3.5 本能反应 | ✅ 每Tick | 仅[婴儿]标签NPC，数量极少（通常<5个），哭/睡/发呆 |
| 4. 欲望计算 | 每5~10 Tick | 降频不影响体验。婴儿跳过，幼儿欲望库小 |
| 5. 行动执行 | ✅ 每Tick | 执行中NPC占比小（多数在等待或移动中） |
| 6. 关系+信息传播 | 每2小时/每5 Tick | 随机配对抽样 |
| 7. 事件检测 | 每Tick | 纯条件判断，极轻 |
| 7.5 事件总线分发 | ✅ 每Tick | 大部分Tick没有事件 → 空转跳过 |
| 8. 市场结算 | 每天一次 | 价格等不会每秒变化 |
| 9. 清理任务 | 每Tick | 过期检查+删除，极轻 |

### 2.2 大规模NPC的调度

```
如果NPC数量上到1000+：
  欲望计算 → 队列化处理（每Tick只算一小部分）
  每个NPC每Tick实际上只执行1~2个"动作单元"
  大部分NPC处于"空闲"状态，不需要全量计算
```

## 三、初始化流程（游戏启动）

> ⚠️ v2.0 更新：支持多世界存档。玩家可选择继续已有世界或创造新世界。
> 完整存档系统设计见 `多世界存档系统.md`。

### 3.1 启动流程

```
游戏启动：
  ┌─ 检查 saves/ 目录下是否有存档（读取 _index.json）
  │
  ├─ 没有存档 ──────────→ 直接进入"创造新世界"界面
  │
  └─ 有存档 ──────────→ 显示世界列表 → 玩家选择：
       [继续世界] → 加载 world_XX，从上次Tick继续
       [创建新世界] → 新建 world_YY
       [删除世界] → 删除对应文件夹
```

### 3.2 创造新世界

```
选定"创造新世界"后：

1. 地图生成
   → 随机生成地形网格（草地+森林+河流+山地）
   → 确保出生点在水域附近

2. NPC生成 ← NPCFactory.createInitialPopulation()
   → 按配置随机生成第一代村民(30~40人)
   → 随机配对夫妻（约10个家庭）
   → 每对夫妻生成0~2个孩子（随机年龄0~16）
   → 为每个NPC创建 saves/world_XX/NPC/{姓名}/个人信息.json

3. 初始欲望触发
   → 每个NPC运行第一次欲望计算
   → 第一个欲望立刻生成 → 第一个动作开始执行

4. Tick循环启动
   → 每隔1/10秒调用一次tick()
```

### 3.3 加载已有世界

```
选定"继续世界"后：

1. 读取 saves/world_XX/世界信息.json → 恢复时间/Tick计数/天气
2. 读取 saves/world_XX/地图.json → 恢复地形+建筑
3. 读取 saves/world_XX/NPC/*/个人信息.json → 恢复所有NPC数据
4. 重建引擎内存映射（辨识符→系统ID、GOAP状态、事件总线监听）
5. Tick循环启动，从恢复的Tick数继续
```

### 3.4 与 NPCFactory 的关系

- **创造新世界** → 调用 `NPCFactory.createInitialPopulation()`
- **加载已有世界** → 不调 NPCFactory，直接读 JSON 文件加载
- **运行时分娩** → 事件总线触发 `NPCFactory.createChild()`

## 四、每Tick的时间用图（性能预算）

```
假设100个NPC，目标每Tick耗时 < 10ms：

  时间推进         →  <0.1ms（纯计数器）
  环境感知         →  <1ms   (距离计算)
  生理状态         →  <1ms   (简单的加减)
  欲望计算×20%  →  <3ms   (效用打分)
  行动执行         →  <3ms   (路径+指令)
  关系社交         →  每2小时执行
  市场结算         →  每天执行
  事件检测         →  <1ms
  渲染(独立于逻辑) →  由GPU处理
  
总预算：约8ms << 16ms（60fps）
```
