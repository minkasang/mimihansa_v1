## 零、核心设计原则：意图在文本之前

```
❌ LLM 模式（不是我们的）:
   文本 → NLP解析 → 推测意图 → 执行

✅ GOAP 标签模式（我们的）:
   欲望 → 意图结构体(带标签) → 选文本(给玩家看) → B收到意图结构体 → B决策 → 选回应文本 → 执行效果

文本只是渲染层！信息传递走的是结构体，不走文本解析。
```

### 1.1 说话风格系统：34维性格 → 不止3种语气

```
❌ 旧方案（太粗糙）:
   一个意图只有 3 种语气（友好/中性/敌意）

✅ 新方案（多轴叠加）:
   每个 NPC 的说话风格不是"选一个语气"，
   而是多个性格维度同时影响的复合结果：

   说话风格 = 礼貌程度 × 情感表露度 × 表达方式 × 耐心度 × 幽默度

   每条轴从 34 维性格中映射：
   
   礼貌程度（0-10）  ← 道德水准_规则遵守 + 社交属性_自我坦露
   情感表露度（0-10）← 情绪基调_积极倾向 + 人际关系_忠诚度
   表达方式（直接/迂回/华丽/简练）← 行事风格_决策模式 + 身体素质_智力
   耐心度（0-10）    ← 外显活力_行动意愿（反向）+ 情绪基调_情绪稳定性
   幽默度（0-10）    ← 行事风格_幽默感

   实际效果：同一个意图"想要苹果"，不同 NPC 说出来的话完全不同：

   礼貌高 + 情感高 + 低幽默   → "不好意思，能分我一个苹果吗？我实在没办法了..."
   礼貌低 + 情感低 + 高幽默   → "嘿，苹果给我一个呗！"
   高书生气 + 高礼貌        → "敢问阁下，此苹果可否割爱相赠？"
   高胆魄 + 低礼貌 + 低耐心  → "把苹果拿来！快点！"
   
   这至少产生 5×5×4×5×5 = 2500 种组合，
   但我们不穷举——用"性格子层"机制按需扩展即可。
```

### 1.2 场景层级（新版）

```
意图大类（8大类，100+子场景）
  │
  ├── 说话风格（多轴复合：礼貌×情感×表达×耐心×幽默）
  │     └── 文本池 key = "意图id.风格子层"（如 "beg_item.polite_warm"）
  │
  └── 回应/决策（B NPC 响应）
        └── 回应类型（每种场景 2~6 种可能）
              └── 决策权重 = B性格 × 对A好感 × 环境因子
                    └── 选中回应 → 取文本 → 执行效果 → 跳转/结束
```

## 二、Key 命名规范（业界参考 + 本项目方案）

### 2.0 你需要知道的一件事

你问我 `"索要物品.友好"` 这种 key 命名 OK 不 OK。让我给你一个业界的参照：

**主流游戏引擎对 dialogue key 的命名方式：**

| 来源 | 命名方式 | 示例 |
|:-----|:--------|:-----|
| Unity Dialogue System | `分组/对话名/节点ID`（路径式） | `NPC/Shopkeeper/Greeting` |
| Ren'Py（视觉小说） | `label_name`（下划线，Python风格） | `shop_greet_first_time` |
| Inkle（80 Days等） | `knot.stitch`（dot notation） | `town.market.gossip` |
| Yarn Spinner（Night in the Woods） | `NodeTitle`（空格+大写） | `Shopkeeper_Greeting` |
| **本项目推荐** | `意图id.风格子层`（dot notation, 中文） | `beg_item.polite_warm` 或 `索要物品.高礼貌高情感` |

**推荐命名规则：**

```
文本池 key = "{意图id}.{说话风格子层}"

意图id（英文简写）:
  beg_item    = 索要物品
  ask_way     = 问路
  greet       = 打招呼
  trade       = 交易
  help        = 求助
  confess     = 表白
  invite      = 邀请
  share_info  = 分享信息
  threaten    = 威胁
  complain    = 抱怨
  ...共约30个意图id

说话风格子层（从5轴复合）:
  polite      = 高礼貌
  blunt       = 低礼貌
  warm        = 高情感
  cold        = 低情感
  direct      = 直接
  winding     = 迂回
  elegant     = 华丽
  terse       = 简练
  patient     = 高耐心
  impatient   = 低耐心
  humorous    = 高幽默
  bookish     = 高书生气
  bold        = 高胆魄
  
组合示例:
  beg_item.polite_warm        → "能分我一个苹果吗？求求了..."
  beg_item.blunt_impatient    → "苹果给我！快点！"
  confess.shy_winding         → "那个...最近天气不错...（就是不敢说出来）"
  ask_way.polite_bookish      → "敢问阁下，麦田往何处去？"
```

**为什么不只用 3 种语气？**

因为 34 维性格产生的说话风格远不止「友好/中性/敌意」。
一个「友好」的人可能说得幽默、说得迂回、说得华丽——
同样一个意图，实际能产生几十种不同的表达方式。
我们的 key 系统用**组合标签**而不是**单一枚举**来覆盖这个多样性。

## 三、核心问题：句型如何绑定标签？如何查找？

### 3.1 答案：不需要"搜索"，是"索引直达"

```
文本库的存储结构是一个嵌套字典：

文本库 = {
  "索要物品": {
    "友好": [ "能给我一个{物品}吗？", "我需要{物品}，方便给一个吗？", ... ],
    "中性": [ "你能把{物品}给我吗？", "那个{物品}可以给我用吗？", ... ],
    "蛮横": [ "把{物品}拿来！", "这东西我看上了，给我！", ... ]
  },
  "问路": {
    "礼貌": [ "请问{地点}怎么走？", "打扰一下，{地点}在哪个方向？", ... ],
    "直接": [ "{地点}在哪？", "你知道{地点}怎么去吗？", ... ],
    "粗鲁": [ "喂，{地点}往哪走？", "那个{地点}你知不知道？", ... ]
  },
  ...
}
```

**查找流程（零搜索，纯索引）：**

```
意图结构体 = { 意图: "索要物品", 语气: "友好", 物品: "苹果" }
            ↓
Step A: 直接用"索要物品"+"友好"当 key → 文本池索引
            ↓
Step B: 文本池["索要物品"]["友好"] → 取出所有候选句
            ↓
Step C: 随机选一条 → "能给我一个{物品}吗？"
            ↓
Step D: 替换变量 → "能给我一个苹果吗？"
            ↓
Step E: 显示在 NPC 头顶气泡
```

**时间复杂度**：O(1)，就是一个字典取值。不需要遍历、不需要模糊匹配、不需要 NLP。

### 3.2 通用句型 vs 固定句型

你提到的"我想要一个什么可以给我吗"这类**通用句型**，正是文本池的核心：

```
通用句型（可替换变量）：
  "能给我一个{物品}吗？"
  "我想要{物品}，可以吗？"
  "把{物品}拿过来！"
  "请问{地点}怎么走？"
  "能帮我{任务}吗？"
  "你知道{信息}吗？"

固定句型（某些特定场景）：
  "你愿意做我女朋友吗？"          ← 表白，不需要变量
  "滚远点！"                      ← 威胁驱逐，不需要变量
  "好久不见，你还好吗？"          ← 老友重逢，固定表达
```

**两种句型在同一个文本池里混合存放**，查找机制完全一样——固定句型的 `{}` 变量位为空而已。

### 3.3 同一个意图，不同性格的 NPC 怎么说

```
意图: 索要物品, 语气: 友好

善良=8, 社交欲=7 → "不好意思打扰了，能分我一个{物品}吗？我实在没办法了..."
```

## 四、B（接收方 NPC）的决策引擎：怎么决定回应？

### 4.1 决策公式（以「索要物品」为例）

```
对每个可能的回应类型，计算权重：

回应"大方给" 权重 = 基础10
  × 善良乘数:    善良≥7 → 1.5, 善良4~6 → 1.0, 善良<4 → 0.5
  × 好感乘数:    好感≥60 → 1.5, 好感≥30 → 1.2, 好感<0 → 0.3
  × 贪婪惩罚:    贪婪≥7 → 0.5, 贪婪4~6 → 0.8
  × 物品因素:    该物品有多余(>1) → 1.3, 该物品只有1个 → 0.6
  × 公共场合:    周围有人看着 → 1.2（怕被说小气）
  = 最终权重

回应"委婉拒绝" 权重 = 基础5
  × 社交欲:      社交欲≥7 → 1.5（不想得罪人）
  × 好感乘数:    好感<30 → 1.3
  × 猜疑:        猜疑≥6 → 1.3（"他为什么找我要？"）
  × 物品因素:    该物品很重要 → 1.4
  = 最终权重

回应"直接拒绝" 权重 = 基础3
  × 善良反向:    善良≥7 → 0.3（狠不下心）
  × 勇气:        勇气≥7 → 1.5
  × 好感反向:    好感≥30 → 0.5
  × 心情低落:    开心<4 → 1.4（心情不好容易发火）
  = 最终权重

回应"愤怒驱赶" 权重 = 基础1
  × 愤怒值:      当前生气 → 3.0
  × 记仇:        记仇≥8 → 2.0
  × 好感反向:    好感< -20 → 2.0
  × 善良反向:    善良≥5 → 0.2
  × 力量对比:    B力量 > A力量 → 1.3
  = 最终权重
```

每个回应类型的权重归一化为概率，然后随机抽取。

## 七、查找机制详解：从意图到文本的一句话

### 7.1 查找不是"搜索"，是"拼 key"

```typescript
// 伪代码：文本选择器
function selectText(
  文本标签: string,      // 如 "索要物品.友好"
  npc性格: Record<string, number>,
  变量: Record<string, string>
): string {

  // Step 1: 拼出 key → "索要物品.友好"
  const pool = 文本库.文本池[文本标签];

  // Step 2: 匹配性格子层
  let candidatePool = pool["默认"];  // 兜底

  // 遍历 npc 的高维度性格（≥7），看有没有特殊池
  const highTraits = [];
  if (npc性格["道德水准_利他意愿"] >= 7) highTraits.push("高善良");
  if (npc性格["后天气质_书生气"] >= 7) highTraits.push("高书生气");
  if (npc性格["行事风格_幽默感"] >= 7) highTraits.push("高幽默");
  if (npc性格["胆魄气量_勇气阈值"] >= 7) highTraits.push("高胆魄");
  // ... 更多维度

  // 多个高维度时随机选一个（每个 NPC 每次说话可能有不同的"腔调"）
  if (highTraits.length > 0) {
    const picked = highTraits[Math.floor(Math.random() * highTraits.length)];
    if (pool[picked]) candidatePool = pool[picked];
  }

  // Step 3: 随机选一条句型
  let text = candidatePool[Math.floor(Math.random() * candidatePool.length)];

  // Step 4: 替换变量
  for (const [key, val] of Object.entries(变量)) {
    text = text.replace(new RegExp(`\\{${key}\\}`, 'g'), val);
  }

  return text;
}
```

**整个过程没有遍历、没有模糊匹配、没有 NLP。就是字典取值 + 条件判断。O(1) 复杂度。**

### 7.2 为什么不需要 LLM？

```
LLM 做的事:
  输入: "请问麦田往哪边走啊？"
  内部: (N 亿参数, 数秒推理)
  输出: "这个人在问路，他想去麦田..."

标签系统做的事:
  输入: 意图结构体 { 意图:"问路", 目标地点:"麦田" }
  输出: (不需要处理，意图已经在结构体里了)
```

**意图不来自文本 — 意图来自欲望触发。文本只是贴在意图上的 UI 糖衣。**

## 八、说话风格的多轴判定（替代旧的单一语气）

```
每个 NPC 的说话风格由 5 条轴共同决定，不是简单选"友好/中性/敌意"：

轴1: 礼貌程度 = (道德水准_规则遵守 × 0.6 + 社交属性_自我坦露 × 0.4) / 10
   0-3: 粗鲁   4-6: 中性   7-10: 有礼

轴2: 情感表露度 = (情绪基调_积极倾向 × 0.5 + 人际关系_忠诚度 × 0.5) / 10
   0-3: 冷淡   4-6: 适中   7-10: 热情

轴3: 表达方式 ← 行事风格_决策模式 + 身体素质_智力
   ≥7理性 → "直接"     ≥7感性 → "迂回"
   高书生气 → "华丽"    低智力+低社交 → "简练"

轴4: 耐心度 = (外显活力_行动意愿的反向 × 0.6 + 情绪基调_情绪稳定性 × 0.4) / 10
   0-3: 急躁   4-6: 中性   7-10: 耐心

轴5: 幽默度 = 行事风格_幽默感 / 10

这 5 条轴组合起来产生文本池的"风格子层" key：
  例如：礼貌=8(有礼) + 情感=7(热情) + 表达=华丽 + 耐心=6 + 幽默=4
  → key = "polite_warm_elegant"

但实际使用时我们不需要如此精细的 key——只要前两条轴 （礼貌+情感），
加上可选的特殊标签 （bookish/humorous/bold），就足以产生丰富的多样性。

示例：
  张文博: 礼貌8, 情感6 → key = "polite_warm", 高书生气 → 附加后缀 "_bookish"
  齐玲玲: 礼貌6, 情感5 → key = "neutral_mid"
  王大锤: 礼貌2, 情感3 → key = "blunt_cold"

引擎选文本时：
  先拼 key = "意图id.polite_warm"
  查文本池 → 有 → 再用高维度性格(bookish)做二次筛选
  查文本池 → 没有 → 降级到 "意图id.neutral_mid"
  还没有 → 降级到 "意图id.默认"
```
