﻿﻿﻿﻿# NPC创建模块（NPCFactory）

> ⚠️ 规范研究文档。定义 NPC 数据文件的创建、初始化和遗传继承逻辑。
> 本模块不是 Tick 循环中的常规步骤——它是**工具模块**，被两个入口调用：
> 1. 游戏启动时（世界初始化）
> 2. 分娩事件触发时（事件总线回调中）

---

## 一、模块职责

```
NPCFactory
├── createInitialPopulation(n, mapBounds)  → 世界初始化：批量随机生成始祖NPC
├── createChild(mother, father, location)  → 分娩创建：继承父母基因+随机变异
├── createNPCFolder(npc)                   → 创建NPC文件夹和JSON文件
└── initNPCData(npc, source)               → 初始化NPC所有参数（来源：随机 或 遗传）
```

---

## 二、世界初始化：随机生成第一批NPC

### 2.1 调用时机

在引擎架构 §三 初始化流程的第3步调用（`初始世界生成.md` 中定义）：

```
游戏启动 → 地图生成 → NPCFactory.createInitialPopulation(30~40, mapBounds)
```

### 2.2 生成逻辑

```
函数: createInitialPopulation(count: number, bounds: Rect): NPC[]

对每个NPC:
  1. 生成唯一 id: "npc_" + uuid
  2. 性别: randomPick(["男", "女"])
  3. 年龄: random(18, 50)（第一代全是成年人）
  4. 生理状态: 全部初始值（饥饿度=3, 口渴度=3, 疲劳度=2...）
  5. 性格: 34维各 random(1, 10)
  6. 天赋: 各维 random(1, 10)
  7. 素质: 力量/敏捷/智力等各 random(1, 10)
  8. 技能: 全部 = 0（始祖NPC从零开始）
  9. 外貌: 各维 random
  10. 物品栏: []
  11. 金钱: random(0, 50)
  12. 标签: [成年]
  13. 社会关系: 空（还没有建立关系）
  14. 知识库: []（对这个世界一无所知）
  15. 家坐标: null（还没建房子）
  16. 工作场所ID: null
  17. 周期数据（女性）: 初始化经期系统
  18. 寿命上限: 按死亡系统公式计算
  19. 当前位置: 地图上的随机可行走坐标
  20. 创建 NPC/{姓名}/ 文件夹，写入 JSON
```

### 2.3 初始家庭关系

始祖NPC生成后，引擎会调用一个额外步骤建立初始家庭关系（约10个家庭）：

```
将NPC随机配对为夫妻:
  1. 随机将成年男女两两配对
  2. 每对夫妻写入彼此的社会关系：
     配偶.配偶ID = 对方ID
     配偶.标签：如果有 [已婚]
  3. 每对夫妻创建 0~2 个孩子（随机年龄 0~16）
  4. 写入父母/子女关系：
     父母.社会关系.子女ID.push(child.id)
     子女.社会关系.父母ID = [mother.id, father.id]
     子女.标签: 按年龄打 [婴儿]/[幼儿]/[学龄]/[青少年]
  5. 家庭成员之间写入知识库：
     - 互相认得的辨识符映射（引擎内存）
     - 知识库里写"人物"类型条目：{辨识符, 称呼, 关系标签}
```

## 三、分娩创建：createChild()

### 3.1 调用时机

事件总线收到"分娩完成"事件 → 回调中调用此函数。

**注意**：此调用发生在 Step 7.5（事件总线分发），不占用 Tick 循环的常规步骤。

### 3.2 婴儿数据生成

```
函数: createChild(mother: NPC, father: NPC | null, location: [number, number]): NPC

入参:
  mother: 母亲的完整 NPC 数据
  father: 父亲的完整 NPC 数据（可能为 null——不知道父亲是谁）
  location: 出生位置（通常 = 母亲当前位置）

生成逻辑:

  1. id: "npc_" + uuid
  2. 姓名: 空（婴儿没有名字，后期由父母/自己命名）
  3. 性别: 查询清宫表.json 或随机（未知父亲时随机）
  4. 年龄: 0
  5. 出生日期: World.时间.当前Tick
  6. 寿命上限: 按死亡系统公式计算（基于遗传健康值）
  
  7. 生理状态（婴儿初始值）:
     饥饿度: 1（刚吃饱，但很快就会饿）
     口渴度: 1
     疲劳度: 1
     精力: 80
     开心值: 5（中性）
     健康值: 按遗传公式计算（见下方 3.3）
     性欲值: 0（婴儿没有）
  
  8. 素质（遗传 + 变异）:
     力量: clamp(parentMean_力量 × 0.6 + random(1,10) × 0.4, 1, 10)
     身手敏捷: 同上
     移动速度: 同上
     耐力: 同上
     智力: 同上
     情商: 同上
     ...（所有素质类参数按此公式）
  
  9. 性格（34维遗传）:
     每维 = clamp(parentMean × 0.67 + random(1,10) × 0.33, 1, 10)
     如果 father 为 null → 母亲的性格 × 0.7 + random × 0.3
  
  10. 天赋: 同样遗传 + 变异公式
  
  11. 技能: 全部 = 0
  
  12. 外貌:
      身高: parentMean × 0.7 + random × 0.3
      长相分: parentMean × 0.5 + random × 0.5（婴儿长相随机性更大）
  
  13. 物品栏: []
  14. 金钱: 0
  15. 标签: [婴儿, 需要照料, mother.姓名+的后代, mother.家族]
  16. 社会关系:
      父母ID: [mother.id] + (father ? [father.id] : [])
      好感度: {}（空，还没建立）
  
  17. 知识库: []（完全空白——婴儿不认识任何人）
  18. 家坐标: mother.家坐标（跟母亲住一起）
  19. 工作场所ID: null
  20. 当前位置: location（母亲旁边的空位）
  
  21. 周期数据（女婴）:
      是否怀孕: false
      其他: 全部初始值
  
  22. 创建 NPC/{id}_未命名/ 文件夹，写入 JSON
```

### 3.3 健康值遗传

```
婴儿.健康值 = clamp(
  parentMean_健康 × 0.7 + random(1,10) × 0.3,
  1, 10
)

如果父亲为 null → 母亲健康值 × 0.8 + random × 0.2
```

### 3.4 婴儿出生后需要写入的外部数据

创建婴儿后，还需要更新：

```
母亲:
  社会关系.子女ID.push(baby.id)
  标签: [哺乳期]（自动添加，不需要感知）
  知识库: 写入一条"人物"类型的条目
    - 引擎内存映射: baby系统ID → 母亲专属辨识符（如 r_child_01）
    - { 辨识符: "r_child_01", 称呼: "我的孩子", 标签: [婴儿, 需要照料] }

父亲（如果存在）:
  社会关系.子女ID.push(baby.id)
  知识库: 同上写入"人物"条目（但只有当他感知到婴儿时才写——见下方§五）

引擎内存:
  建立其他 NPC 的辨识符映射（所有后续感知到婴儿的 NPC）
```

## 五、信息壁垒：父母认知 vs 系统数据

婴儿出生后有一个信息壁垒的关键场景：

### 母亲
- **亲身经历了分娩** → 系统在分娩完成后直接往她的知识库写"我生了一个孩子"。这符合信息壁垒（亲身经历）。
- 同时也写入婴儿的辨识符映射。

### 父亲
- 如果父亲在分娩现场（感知范围内） → 他的 Step 2 会感知到"齐玲玲旁边多了一个婴儿" → 引擎匹配辨识符 → 写入知识库。
- **如果父亲不在现场** → 他暂时不知道孩子出生。要等到他回家或用其他方式获知。
- 系统**不能**在父亲不在场的情况下直接往他的知识库写"你有了一个孩子"。
- 父亲是否知道可以通过口口相传——邻居看到婴儿后告诉父亲，或母亲亲口说。

### 母亲家族谱系
- 母亲的社会关系里，子女ID会由系统直接写入（这是引擎内部数据，用来追踪家族谱系）。这不违反信息壁垒，因为这是**引擎模块自己用的数据**，不进入母亲的决策计算。
- 母亲的**决策计算**只读自己的知识库——而她知识库里已经有"我的孩子"这个条目（亲身经历写入的），所以她的行为会包含照顾孩子。

## 六、与现有系统的衔接

| 系统 | 衔接点 |
|:-----|:-------|
| 引擎架构 §三 初始化 | 调用 createInitialPopulation() |
| 出生系统 §分娩 | 分娩完成 → 事件总线回调 → createChild() |
| 事件总线（§13） | 收到"分娩完成"事件 → 调用 NPCFactory |
| IO 注册表 | 本模块不直接挂载 Tick 步骤——操作通过事件总线回调触发 |
| 感知系统 §辨识符 | 创建婴儿后需要建立其他NPC对婴儿的潜在辨识符映射 |
| 童年教育系统 | 婴儿标签、年龄切换逻辑 |
| 死亡系统 | 婴儿的寿命上限由 NPCFactory 在创建时计算 |

## 八、婴儿命名机制（v1.1 新增）

> ⚠️ 婴儿出生时姓名为空。由父母在出生后的互动中起名。

### 8.1 命名触发

```
婴儿出生后，父母的知识库里已经有了婴儿的人物条目:

母亲:
  知识库: { 辨识符:"r_child_01", 称呼:"我的孩子", 类型:"人物" }

父亲（如果在场并感知到了）:
  知识库: { 辨识符:"r_child_02", 称呼:"我的孩子", 类型:"人物" }

命名触发（发生在 Step 6 社交互动中）:
  父母聊天时（或主动发起）:
    父亲: "孩子该有个名字了"
    母亲: "是啊，叫什么好呢？"

  → 由父母中 书生气 更高的那一位执行命名动作
  → 从 姓氏表 中取父亲的姓氏
  → 从 名字表 中按性别随机选取名字
  → 写入: 婴儿.姓名 = "陈晓燕"
  
  同时:
    婴儿的文件夹名: npc_baby_089_未命名 → npc_baby_089_陈晓燕
    父母的知识库更新: "我孩子的名字"

命名时机:
  - 优先在出生后 1~3 天内发生（父母社交时自然触发）
  - 如果父母一方不在场（去世/不在家）→ 延迟到另一方能参与时
  - 如果父母双方都去世了 → 由养父母或最近亲属命名
  - 如果没有任何人命名 → 婴儿到 2岁时系统随机生成一个名字（兜底）
```

### 8.2 婴儿认知自己名字的过程

```
婴儿在 0~2 岁时走本能循环，但走 Step 2 感知:

  父母反复叫他的名字 → 婴儿的 Step 2 听到"陈晓燕"这个音
  → 知识库: { 类型:"自身", 内容:"他们叫我'陈晓燕'", 来源:"亲耳", 可信度:1.0 }

  到了幼儿期（2岁+），他开始说"我"和"陈晓燕"——
  这完全来自他婴儿期积累的知识库。
```
