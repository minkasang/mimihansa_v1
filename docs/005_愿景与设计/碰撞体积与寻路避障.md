# 碰撞体积与寻路避障系统

> 设计师口述 → AI整理结构化 → 设计师检查确认
> ⚠️ 设计规格书。所有物体都有体积，NPC 需要实时避障。

---

## 一、体积：万物皆有尺寸

### 1.1 体积定义

```
所有 Agent 和 物体 都有体积属性：

体积 = 该对象在地图上占据的格数
  1 = 占据 1×1 格 (人、兔子、石头、围栏)
  2 = 占据 2×2 格 (鹿、猪、牛、房屋)
  3 = 占据 3×3 格 (大型房屋)

碰撞判定：两个物体不能共享同一格
  if (A.体积 > 0 && B.体积 > 0 && A占据格 ∩ B占据格 != ∅):
    → 碰撞，不能穿过
```

### 1.2 各对象的体积

| 对象 | 体积 | 可否被穿过 | 备注 |
|:-----|:----:|:---------|:-----|
| 人 | 1 | — | 互相不可穿过 |
| 兔子/鸡/猫 | 1 | 可被跨过 | 太小了 |
| 鹿/猪/羊 | 2 | 挡路 | — |
| 牛 | 2 | 挡路 | — |
| 马 | 2 | 可骑乘穿过 | 骑在上面时本体不占格 |
| 狼 | 1 | 挡路 | — |
| 树 | 1 | 不可穿过 | 砍掉后体积=0 |
| 石头 | 1 | 不可穿过 | — |
| 简易草棚 | 2 | 不可穿过 | 有门的那格可以进入 |
| 木屋 | 2 | 同上 | — |
| 石基瓦房 | 3 | 同上 | — |
| 围栏 | 1 | 人可跨过 | 动物体积≤围栏体积→不能跨 |
| 火堆 | 1 | 不可穿过 | — |
| 水域 | 1 | 不可穿过 | 需要游泳（先不做） |
| 山地 | 1 | 不可穿过 | 需要攀爬（先不做） |

## 二、A* 寻路 + 实时避障

### 2.1 寻路模式

NPC 有三种寻路模式，按信息完整度自动切换：

```
模式 A：精确寻路（已知目标坐标）
  前提：NPC 知识库中有目标的精确坐标
  算法：A* 最短路径
  避障：A* 规划时自动绕开不可通行格

模式 B：探索寻路（只有大致方向）
  前提：NPC 只知 "东北偏东方向，约 80 步"
  算法：
    1. 面朝东北方向走 80 步
    2. 每走一步用眼睛扫描 → 看到目标了吗？
    3. 如果没看到 → 到达预定距离后扩大搜索半径
    4. 找到了 → 更新知识库为精确坐标 → 切换到模式 A

模式 C：避障局部绕行（实时）
  前提：A* 规划的路径上突然出现障碍（另一人/动物挡住了）
  算法：
    检测前方一格有障碍 → 侧移一格 → 继续走
    持续被挡 → 重新计算 A*
```

### 2.2 避障的性能预算

```
每 Tick 每个移动中 NPC 的避障开销：
  1. 读当前 A* 路径的下一个节点 → O(1)
  2. 检查下一格是否被占 → O(1)，直接查网格表
  3. 如果被占 → 尝试左右两格 → O(2)
  4. 如果持续被挡 > 3 Tick → 重新 A* → O(n) 但触发概率低

总开销 ≈ NPC 数量 × (O(1) + 偶尔 O(n))
1000 NPC × 0.02ms ≈ 20ms（可接受）
```

##三、动态障碍的处理

### 3.1 "走着走着前面多了一个人"

```
这是最常见的情况——两个 NPC 走同一段路

处理方式：
  后到者（检测到前方有人的那一方）：
    1. 等待 1 Tick（对方可能也在走，马上会让开）
    2. 对方没让 → 侧移一格 → 继续
    3. 侧移也过不去 → 重新 A*

  先到者：
    无需特殊处理，正常行走
```

### 3.2 "一群人挤在同一个路口"

```
多人同向 → 排队，一个一个过（自然速度差）
多人逆向 → 各自侧移让路

不需要复杂的交通规则——NPC 只是检测前方 2 格 → 有人就微调
```

## 四、性能小结

| 操作 | 每 Tick 开销 | 1000 NPC 合计 |
|:-----|:-----------|:------------|
| A* 寻路 (仅新路径) | ~0.1ms | 只有移动中 NPC 触发 |
| 前方占据检测 | ~0.001ms | ≈ 1ms (全部 1000 人) |
| 避障微调 | ~0.001ms | ≈ 0.3ms (偶尔) |
| 网格更新 (每格体积变化) | ~0.001ms | ≈ 1ms |

**结论：碰撞体积不会破坏性能**。体积只是查表（O(1)），A* 只在少数 NPC 移动时触发。
