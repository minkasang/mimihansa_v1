# 水物理规律

> 游戏世界的水行为规范。所有水流效果必须符合本文档的物理模型。

---

## 一、核心概念

### 1.1 三个基本量

| 量 | 范围 | 含义 |
|:---|:----|:-----|
| **地势高度 E** | 0~10 | 该格子/子瓦片的地面绝对海拔。0=最低(河床), 10=最高(山顶) |
| **水量 W** | 0~100 | 该格子上方覆盖的水深量。W=0=干, W=100=满 |
| **水面高度 S** | E + W/WK | 水面离绝对零点的位置。WK=20, 即 W=100 对应 5 格深的水深 |

### 1.2 铁律三条

```
铁律 1 — 等水平面
  若水体 A 和水体 B 是连通的(location相邻且中间无障碍),
  则 Sa = Sb 或水正在从高的一侧流向低的一侧。
  不能在相邻连通格出现 Sa=8.0 和 Sb=3.0 而不发生流动。

铁律 2 — 质量守恒
  封闭系统中的总水量不变。
  水不能凭空产生、不能凭空消失。
  唯一的例外是: 水流源头(Source)可加水、水流归宿(Sink)可吞水。

铁律 3 — 压力驱动
  水流速度 ∝ 水面高度差(S差)。
  S差越大, 水转移越快。
  S差 → 0, 水流停止。
```

## 二、水体类型

### 2.1 死水 (Stagnant Water)

```
定义: 一个封闭的凹陷地势形成的池塘/湖泊, 没有持续水源补给。
行为:
  - 初始有固定水量
  - 被取水 → 水位下降
  - 被填土 → 水被挤到相邻低格
  - 没有水源补充 → 只能被消耗
示例: 一个山间小湖、一个雨水积累的洼地
```

### 2.2 活水 (Flowing Water / Source)

```
定义: 有持续水源补给的河流、溪流。
行为:
  - 有一个或多个"水源格", 每Tick自动补水到指定水面高度
  - 水源格的水量永远不会低于预设值(模拟上游来水)
  - 挖开河道 → 水自动流进来并保持恒定的水面高度
  - 下游堵住或填土 → 水位不会降, 因为水源不断补水
示例: 地图北部山区有泉水, 形成一条从北向南的河流;

        水源格 (x=10, y=0, 目标水面=5.0)
          ↓
        ═══════════════════ 河 流
          ↓                    ↓
        正常格              正常格
        (水从此流过)        (水从此流过)
          ↓
        下游边界 (水流出去=消失, 模拟水流向更低处)
```

## 三、水流公式 (一个 Tick 内的行为)

### 3.1 水流转移量

```
对于相邻子瓦片 A ↔ B:

  Sa = Ea + Wa/WK     (A 的水面高度)
  Sb = Eb + Wb/WK     (B 的水面高度)

  ΔS = Sa - Sb

  if ΔS > 0.01:  # A 比 B 高
    想要转移量 = ΔS × 流速系数 × 20
    实际转移量 = max(0.5, min(想要, A可用水量, B剩余空间))

    Wa → Wa - 实际转移量
    Wb → Wb + 实际转移量

  流速系数 = 0.4 (可调, 越大水流动越快)
```

### 3.2 每 Tick 迭代次数

```
水流是扩散过程, 一次扫描不够。每 Tick 跑 N 轮迭代:

  N = 8 (对于 20×15 的地图)
  N = 16 (对于 300×300 的地图)

  越大水越快地趋于水平面, 但消耗 CPU。
```

### 3.3 特殊情况

```
情况 A: 地势高差过大 (悬崖)
  如果 |Ea - Eb| >= 3:
    水形成瀑布 — 水从高处流向低处, 但在渲染上表现为水流箭头/瀑布动画。
    简化处理: 如果 A 地势高+B地势低+ΔS>0 → 水正常流, 但视觉标记为"快速水流"。

情况 B: 满溢
  如果 Wb = 100 (已满):
    跳过 — 不能再加水。

情况 C: 干涸
  如果 Wa = 0:
    跳过 — 没水可流。
```

## 四、水源规则

```
水源格 (Source Tile):
  - 地势 E_source = 0
  - 目标水面 Starget = 预设值 (如 4.0)
  - 每 Tick: if 当前水面 < Starget:
      W_source → min(100, W_source + (Starget - 当前水面) × WK)
    (即自动补水到目标水面高度)
  - 代价: 全图总水量增加(因为水源无中生有 — 模拟上游来水)

下游消失格 (Sink Tile / Map Edge):
  - 地图边缘的水格子 → 水超过边界 → 消失
  - 或指定下游消失点, 到达该点的水自动减少
  - 代价: 全图总水量减少(模拟水流到下游去了)
```

## 五、玩家操作对水的影响

### 5.1 挖土

```
操作: 降低目标格地势 E → E - 1

物理后果:
  1. 水面 S = E + W/WK, E降低 → S降低
  2. 相邻格 S 高于此处 → 水自动流入(由水流引擎处理)
  3. 若挖到 E=0 → 此时该格成为最低点 → 周围水大量涌入
```

### 5.2 填土

```
操作: 升高目标格地势 E → E + 1

物理后果:
  1. 水面 S = E + W/WK, E升高 → S升高
  2. 若此处有水 → 水面高于相邻格 → 水回流出去
  3. 填到 E=10 → 山丘, 水完全无法存留
```

### 5.3 取水 (舀水/抽水)

```
操作: W → max(0, W - 取水量)

物理后果:
  1. 局部水面 S 降低
  2. 相邻水格的水面高于此处 → 水流入补充 → 整体水位微微下降
  3. 水源格会自动补回
```

## 六、活水 vs 死水的判定依据

```
判定: 该格是否位于一条"从水源格可达的路径"上。

算法 (可用并查集或 BFS):
  1. 标记所有水源格
  2. 从水源格 BFS 向四面扩散:
     如果一个格子地势 ≤ 水源的目标水面 AND (水量 > 0 或 地势低到水能流到):
       该格子 = 活水
  3. 水源 BFS 无法到达的 = 死水(池塘/洼地)

渲染区别:
  活水 → 颜色偏青绿, 有流向箭头
  死水 → 颜色偏暗蓝, 静止
```

## 七、简化版实现 (游戏可用, 非全真模拟)

```
我们不做:
  ✗ 纳维-斯托克斯方程
  ✗ 湍流/层流
  ✗ 表面张力
  ✗ 蒸发/降雨(预留)
  ✗ 水与土壤的渗透(预留)

我们做:
  ✓ 地势 + 水量 → 水面高度
  ✓ 压力驱动: 水面差√流速
  ✓ 等水平面收敛
  ✓ 水源/死水区分
  ✓ 挖土/填土对水流的连锁影响
  ✓ 质量守恒
```
