## 一、五感：NPC怎么感知世界

### 1.1 视觉（眼睛）

```
每个NPC有一个视野属性：
  视野半径 = 基础20格
  增加因素：
    站在高处（山地）→ +10格
    白天/晴天      → +5格
    夜晚/大雾      → -10格
    老年人         → -5格

感知内容（在视野半径内可感知的东西）：
  - 地形、建筑、物品（所有可见物）
  - 其他人（能看到是男是女、大概特征、在干什么）
  - 事件（打架、生火、建造——产生视觉事件）
```

### 1.2 听觉（耳朵）

```
听觉半径 = 基础30格
  说话声音大小影响传播距离：
    小声说话（悄悄话）→ 5格以内可听到
    正常说话         → 15格以内可听到
    大声喊叫         → 30格以内可听到
    建筑/墙壁隔音    → 有墙挡着-10格

感知内容：
  - 别人的说话内容（在听觉半径内→听到"
  - 环境声音（打架声、生火声、砍树声，声音大→传播远）
  - 哭声（婴儿的哭声穿透力强，+10格）
```

### 1.3 嗅觉（鼻子）

```
嗅觉半径 = 基础10格
  风的方向影响：
    顺风 → ×2（上风处闻到下风处）
    逆风 → ×0

感知内容：
  - 食物（有人在烤肉的香味，吸引其他人过来）
  - 火灾（烧焦味——可能触发避险）
  - 腐烂（尸体的臭味——注意，这里有东西死了）
```

### 1.4 触觉（默认全感知）

```
触觉不需要范围——身体接触到的自动感知。
感知内容：
  - 被人碰到 → 产生触觉事件
  - 冷/热 → 天气系统的暴露度
```

### 1.5 五种感官的数据结构

```typescript
interface NPCSenses {
  视野半径: number;     // 由视力+环境确定
  听觉半径: number;     // 固定30，受发言音量影响
  嗅觉半径: number;     // 固定10
  触觉: boolean;        // 总是true
  
  当前看到的内容: PerceptionResult[];  // 每Tick更新
  当前听到的内容: PerceptionResult[];
  当前闻到的内容: PerceptionResult[];
}

interface PerceptionResult {
  类型: '视觉' | '听觉' | '嗅觉' | '触觉';
  目标: string;        // 是什么（建筑ID/NPC ID/事件名称）
  距离: number;
  详情: object;        // 具体信息（说的话内容、味道类型等）
}
```

## 二、口口相传：信息传播

### 2.1 聊天是怎么发生的

```
两个NPC在各自的听觉半径内 → 可能触发聊天

聊天的条件：
  1. 双方都不是[战斗]状态
  2. 双方没有仇恨关系
  3. 至少一方有[社交]的意愿
  4. 双方距离 < 听觉半径

聊天频率：
  朋友/熟人 → 每隔几天会自然聊一次
  陌生人   → 如果没事，可能也会路过打招呼
```

### 2.2 聊什么（信息交换）

```
聊天时，双方从自己的知识库中各取一条信息分享：

分享优先级：
  1. 最近发生的大事（如"昨天我打到了一只鹿" "某家生了孩子"）
  2. 对方不知道但自己知道的（信息差）
  3. 闲话/八卦

A告诉B → B的知识库新增一条：
  来源：A告诉我的
  内容：A说的内容
  可信度：取决于B对A的信任（如果A是个骗子，B可能不信→待未来扩展）

B也能告诉C → C再告诉D → 信息扩散
扩散时长：一个消息从孤立的A传到全村（100人）：约2~3天
```

### 2.3 谣言与信息失真（可选，先预留）

```
当信息传递超过3手：
  传递每多一手 → 信息失真概率 +20%

失真效果：
  原始消息："张三昨天打到了一只鹿"
  5手之后："听说张三家跑出来一群鹿"
  10手之后："山里的鹿群要来踩我们的田了"

这个机制让"道听途说"的文化功能真实再现
```

### 2.4 公示栏——另一种传播方式

```
公示栏读写双向（职业与市场系统 §4.1）

与口口相传的区别：
  公示栏 → 一次写入，多人读取（可持久，但需要主动去看）
  口口相传 → 点到点传播（依赖社交，可能失真）

两者互补：
  公示栏存在 → 陌生人也可以获取信息（不需要认识任何人）
  公示栏不存在→ 信息只能走社交网络
```

## 三、信息传播的边界——NPC不能知道什么

### 3.1 已知 vs 未知的判定

```
NPC知道某条信息的条件（满足一个就行）：
  ✅ 亲眼看到了
  ✅ 亲耳听到了
  ✅ 别人告诉他的（记忆库里有记录）
  ✅ 公示栏上看到的

NPC不知道的条件（所有条件都不满足）：
  ❌ 不在视觉/听觉范围 → 不可能知道
  ❌ 没有在公示栏看过 → 不可能知道
  ❌ 没人告诉他 → 不可能知道
```

### 3.2 常识：当大部分人知道了

```
"常识"的判定：
  在某个地理范围内（同村），有已知信息的NPC人数 >= 总人数的80%
  → 该信息标记为"常识"

常识的效果：
  - 新NPC来到村子 → 可能很快听到"常识"（因为80%的人都知道，聊着聊着就会说）
  - NPC可以"常识"为依据做决策（不需要被动去收集信息）
```

### 3.3 个人隐私 vs 公开信息

```
公开信息（对话中自动分享）：
  - 天气
  - 村里发生的大事
  - 自己见到的东西

个人隐私（不会主动分享）：
  - 自己的内心状态（难过、焦虑）
  - 对他人的负面评价
  - 自己做了坏事
  - 自己有多少钱

是否分享隐私取决于性格：
  社交属性_自我坦露 ≥ 7 → 可能主动分享心事
  人际关系_猜疑程度 ≥ 7 → 什么都不说
  情绪基调_积极倾向 ≤ 3 → 心情不好时什么都不会透露
```

## 四、与现有系统的衔接

| 系统 | 衔接点 |
|:-----|:-------|
| 公示栏 | 另一条信息获取渠道 |
| 社交网络 | 口口相传基于朋友关系 |
| 找工作 | NPC通过感知口口相传获得就业信息 |
| 社会秩序 | 看到/听说坏事→好感度下降 |
