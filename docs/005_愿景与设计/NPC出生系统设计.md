## 一、欲望：色欲与性欲的关系

### ⚠️ 色欲 ≠ 性欲（重要修正！）

两者是不同概念，区分如下：

| 概念 | 类型 | 说明 | 变化特征 |
|:----|:----|:------|:--------|
| **色欲** | 性格/欲望（人设） | 好色程度——对异性的兴趣强弱。是**性格底色** | 相对稳定，弹性性格可微调 |
| **性欲** | 生理状态（动态） | 当下的生理冲动——身体想不想。是**临时状态** | 波动很大，每天/每小时变化 |

**关系链：**
```
色欲(高) + 暧昧环境 + 亲密对象 → 性欲值上升 → 可能触发周公之礼
色欲(低) + 没有暧昧 → 性欲值不高 → 不容易触发
```

### 性欲值的设计

```
性欲值 = f(色欲, 环境加成, 对象好感, 时间因子)

色欲基础：
  色欲1-3  → 性欲基础值10（不太想）
  色欲4-6  → 性欲基础值30（中等）
  色欲7-10 → 性欲基础值50（很想）

环境加成（累加到基础值）：
  双方[独处]且无旁人在场          → +15
  双方[亲密关系]（配偶/情侣）      → +20
  环境[暧昧]（夜晚+室内+安静）     → +10
  对方外貌分>7                     → +10
  对方好感度>30                    → +10

时间因子：
  距上次周公之礼超过7天 → ×1.2
  距上次周公之礼超过30天 → ×1.5
  距上次周公之礼3天内 → ×0.3（不重复触发）

性欲值>60 → 触发欲望"do_周公之礼"，进入行动队列
```

### 暧昧标签（新增！）

| 标签 | 触发条件 |
|:-----|:---------|
| `[独处]` | 周围N格内只有双方二人 |
| `[夜晚]` | 游戏时间在晚间 |
| `[室内]` | 双方在同一建筑内 |
| `[安静]` | 周围没有嘈杂事件 |
| `[亲密关系]` | 双方是配偶/情侣 |

## 二、周公之礼的触发流程（程序化）

```
// 每Tick检查 NPC的性欲欲望

Step 1：NPC的性欲值 > 60？
  ├─ 否 → 不触发
  └─ 是 → 进入Step2

Step 2：感知范围内有合适的异性对象？
  ├─ 否 → 不触发
  └─ 是 → 选择好感度最高且满足条件的异性

Step 3：检查环境条件：
  - 双方都在善意/中性的社交状态（非仇恨/战斗）
  - 环境标签满足[独处]或双方在建筑中
  ├─ 不满足 → 不触发
  └─ 满足 → 进入Step4

Step 4：发起方生成动作"action_周公之礼"
  - 步骤1：走向目标NPC
  - 步骤2：目标判定是否同意
    同意条件公式：
      暧昧环境分 = (有[独处]?20:0) + (有[夜晚]?10:0) + (有[室内]?10:0) + (有[安静]?5:0) + (有[亲密关系]?15:0)
      agreeScore = 对方性欲值×0.4 + 对方对发起方好感度/100×0.3 + 暧昧环境分×0.3
      agreeScore > 35 → 同意
      agreeScore ≤ 35 → 拒绝（触发"被拒绝"事件，发起方心情-3）
  - 步骤3：双方都同意 → 执行周公之礼
  - 步骤4：效果结算
    → 双方开心值+5（基础）
    → 双方[快乐值]+10~20（受男性性表现力影响，见参数总表）
    → 女性可能怀孕（见下节）
    → 双方关系标签更新
```

## 三、经期系统

### 3.1 周期数据结构

每个女性NPC维护一个周期状态对象：

```typescript
interface MenstrualCycle {
  周期长度: number;          // 21~35，出生时随机
  生育力: number;            // 0~10，来自参数总表，越高越容易受孕、排卵越稳定
  当前周期日: number;        // 每天+1，到周期长度后归零
  上次月经日: Tick;          // 时间戳
  是否闭经: boolean;
  是否怀孕: boolean;
  孕期天数: number;          // 如果怀孕中，已怀孕了多少天
}
```

### 3.2 每日Tick更新

```
每天Tick时：
1. 是否怀孕？
   是 → 孕期天数+1 → 不更新周期
   否 → 继续

2. 是否生病？or 健康<3？
   是 → 暂停周期（当前周期日不变）
   否 → 继续

3. 今天是否情绪极度低落（开心值<2）？
   是 → 排卵调整值 + random(2,5)天（延迟排卵）
   
4. 当前周期日 +1
5. 如果当前周期日 >= 周期长度 → 周期日归零（新周期开始）
```

### 3.3 排卵窗口计算

```
排卵日 = 周期长度 - 14
排卵日调整 = 排卵日 ± floor((10 - 开心值) / 2)    // 开心值越低，偏移越大
                ± floor((10 - 健康值) / 3)         // 健康越差，偏移越大
                ± floor((10 - 生育力) / 3)         // 生育力越低，排卵越不稳定

最终排卵日 = clamp(排卵日 + 排卵日调整, 周期长度-18, 周期长度-10)

排卵窗口 = [最终排卵日 - 5, 最终排卵日 + 1]   // 6天窗口
```

### 3.4 受孕判定

```
周公之礼发生时：
  if 女性.当前周期日 not in 排卵窗口 → 怀孕概率 = 0%
  if 女性.当前周期日 in 排卵窗口 → 按公式计算：
  
  受孕概率 = 窗口内基础率(25%) × 生育力系数 × 年龄系数 × 意图系数
  
  生育力系数：
    生育力 / 10  → 基础系数(0.1~1.0)
    → 生育力系数 = 基础系数 × 2.0   // 范围0.2~2.0，默认居中=1.0
  
  年龄系数：
    20-30岁 → 1.0
    30-35   → 0.7
    35-40   → 0.4
    40-45   → 0.15
    45+     → 0.0（闭经）
  
  意图系数：
    想要孩子 → 1.2
    无所谓   → 1.0
    不想要   → 0.2

执行判定：
  if random(0, 1) < 受孕概率 → 怀孕
```

## 四、想要孩子（综合打分公式）

触发因素：NPC结婚后，每次周公之礼前系统计算一次"生育意愿"。

### 4.1 社会道德约束（前置检查）

```
⚠️ 社会规则：游戏世界中的"结了婚才能要孩子"是社会道德规范
  
前置检查：NPC是否已婚？
  ├─ ✅ 已婚 → 正常进入生育意愿打分
  └─ ❌ 未婚 → 检查道德约束
       道德水准_底线意识（道德底线）：
         底线高(≥7)  → 遵守社会规范，不想要非婚生子 → 生育意愿=0
         底线中(4-6) → 内心纠结，生育意愿 × 0.5
         底线低(≤3)  → 不在乎社会规范 → 正常进入打分
```

### 4.2 综合打分

```
生育意愿 = Σ(各因素得分 × 权重)

因素1：已有孩子数（反向，越少越想生）
  无孩子 → 100分
  1个    → 60分
  2个    → 30分
  3个    → 10分
  4个+   → 0分

因素2：家庭经济
  家庭金钱/月支出（估算）
  比值>3 → 100分（富裕，养得起）
  比值1-3 → 50分
  比值<1 → 0分（太穷，养不起）

因素3：年龄
  18-30岁 → 100分
  30-35   → 70分
  35-40   → 30分
  40+     → 10分

因素4：责任心（道德水准_规则遵守）
  责任心7-10 → 80分（觉得应该留后代）
  责任心4-6  → 50分
  责任心1-3  → 20分

权重：
  已有孩子数 × 0.3
  家庭经济   × 0.3
  年龄       × 0.2
  责任心     × 0.2

综合得分 ≥ 50 → "想要孩子"
综合得分 30-50 → "无所谓"
综合得分 < 30 → "不想要"
```

> 社会道德规则（如"先婚后育"）可以做成可配置项，放在 `data/libraries/社会规则配置.json` 中，方便调整。

## 五、流产（量化）

```
流产风险 = 基础风险(5%) + 事件加成

事件加成：
  被攻击：
    攻击伤害值 > 3 → +20%流产风险
    攻击伤害值 1-3 → +10%
    攻击伤害值 < 1 → +5%
  
  摔倒/跌倒（由环境事件触发）：
    → +10%流产风险

孕期阶段系数：
  孕早期(1-3月)：流产风险 ×1.5
  孕中期(4-7月)：流产风险 ×1.0
  孕晚期(8-10月)：流产风险 ×0.5

最终流产概率 = 流产风险 × 孕期阶段系数

判定：if random(0, 100) < 最终流产概率 → 流产
流产效果：孕妇心情-10，健康-2，怀孕状态清零
```

### 8.1 性格遗传

```
孩子性格初值 = clamp(parentMean × 0.67 + randomUnif(1,10) × 0.33, 1, 10)

```

## 十、婴儿行为

### 10.3 孤儿被救助的量化

```
每天Tick时，检查所有孤儿：
  if 孤儿.饥饿度 > 7（快饿死了）:
    扫描孤儿感知范围内所有NPC
    对每个NPC计算"救助意愿"：
      救助意愿 = 道德水准_同理心 × 0.6 + 道德水准_利他意愿 × 0.4
      救助意愿 > 5 → 此NPC有概率触发投食动作
      概率 = (救助意愿 - 5) / 5 × 50%   // 最高50%
    
    if 没有任何NPC触发救助:
      孤儿.饥饿度持续上升
      if 孤儿.饥饿度 >= 10:
        → 饿死（死亡处理）
```

## 十三、分娩状态机（v3.1 新增）

> ⚠️ 分娩不是一个瞬间事件，而是一个**状态过程**。从临产到分娩完成，跨越多个 Tick。

### 13.1 状态流转

```
                                      ┌──────────────────┐
                                      │   正常孕期状态    │
                                      └────────┬─────────┘
                                               │ 孕期天数 >= 285
                                               ▼
                                      ┌──────────────────┐
                                      │   临产（寻找安全   │
                                      │   安静的分娩地点） │
                                      └────────┬─────────┘
                                               │ 到达家/安全地点
                                               ▼
                                      ┌──────────────────┐
                                      │     分娩中         │
                                      │  （持续 N 个 Tick）│
                                      └────────┬─────────┘
                                               │ 分娩完成
                                               ▼
                                      ┌──────────────────┐
                                      │   产后虚弱期       │
                                      │ （通过生理状态自然  │
                                      │  驱动，非独立状态） │
                                      └──────────────────┘
```

### 13.2 阶段一：临产（孕期天数 >= 285）

```
触发条件: NPC.孕期天数 >= 285 且 当前不在分娩中

Step 3（生理推演）检测到 → 标记 NPC 进入临产状态:

  标签: 添加 [临产]（外部可见——其他人看到她状态不对）
  
  行为变化:
    - 当前正在执行的任何目标被打断
    - 生成最高优先级目标: "找一个安全安静的地方分娩"
  
  Step 4（欲望计算）：
    临产状态下，分娩欲望优先级 >= 10（高于一切）
    生成目标: action_go_labor（前往家/安全地点）
  
  Step 5（行动执行）：
    执行 action_go_labor:
      1. 优先目标: 自己的家（有床）→ 移动到床边
      2. 次选: 安静、室内、附近无危险的地方
      3. 如果没有任何安全地点 → 原地进入分娩

    行动规则:
      - 移动速度为正常速度 × 0.5（肚子大了走得慢）
      - 如果体力耗尽 → 原地坐下休息 → 恢复后继续
      - 这个过程中不能被社交/闲聊打断
```

### 13.3 阶段二：分娩中

```
触发条件: NPC 到达目标位置（家/安全地点）且标签包含 [临产]

进入分娩状态:
  标签: 移除 [临产]，添加 [分娩中]（外部可见）
  
  持续 Tick 数: random(100, 300) Tick（约 1.6~5 分钟现实时间，模拟 1~3 小时游戏时间）
  
  每 Tick:
    体力 -1
    疲劳度 +0.1
    压力值 +0.1
  
  行为:
    - 完全无法移动
    - 无法执行任何其他动作
    - 无法被打断（除非战斗/灾难）
    - 不需要站起、不需要走路——就是一个持续的"分娩"动画状态
  
  如果体力耗尽（<= 0）:
    - 分娩仍然继续（生理上无法停止）
    - 健康值 -0.5（难产风险，体力耗尽时每 Tick 额外消耗健康）
    - 如果健康值降到 0 → 产妇死亡（难产致死）
```

### 13.4 阶段三：分娩完成

```
触发条件: 分娩持续 Tick 数达到设定值

分娩完成时的效果结算:
  
  1. 重置怀孕状态:
     - 孕期天数 = 0
     - 是否怀孕 = false
  
  2. 创建婴儿:
     - 调用 NPCFactory.createChild(mother, father, location)
     - location = 母亲旁边的空位（1格范围内）
  
  3. 母亲生理状态变化:
     - 体力 -5（消耗巨大）
     - 疲劳度 +5
     - 开心值 +3（孩子诞生是高兴的事）
     - 健康值 -1（分娩伤身）
  
  4. 母亲标签更新:
     - 移除: [分娩中], [临产]
     - 添加: [哺乳期]
  
  5. 母亲知识库写入（亲身经历）:
     写入一条"经历"类型的知识条目:
     {
       类型: "经历",
       内容: "我刚刚生了一个孩子",
       来源: "亲身",
       可信度: 1.0,
       时间戳: World.时间.当前Tick
     }
     
     写入一条"人物"类型的知识条目:
     {
       类型: "人物",
       辨识符: "r_child_01",  // 引擎内部分配的辨识符
       称呼: "我的孩子",
       来源: "亲身",
       可信度: 1.0,
       我眼中的TA: {
         外貌: { 颜值: 待更新, 身高: "婴儿", 体型: "婴儿" },
         标签: ["婴儿", "需要照料", "我的孩子"]
       },
       见面记录: [{ 次数: 1, 时间: "出生时", 地点: "家", TA在干什么: "刚出生" }]
     }
  
  6. 事件总线:
     发出"分娩完成"事件:
     { 类型: "分娩完成", 来源: mother.id, 数据: { 婴儿ID, 父亲ID, 位置 } }
     → 其他系统可以监听此事件（如人口统计 +1）
```

### 13.5 多胞胎处理

```
如果触发多胞胎：
  1. 每个婴儿调用一次 createChild()（双胞胎 → 调用两次）
  2. 母亲生理消耗 × 1.5（双胞胎消耗更大）
  3. 两个婴儿出生位置相邻（相邻格）
```

## 十四、产后恢复与照料链条（v3.1 新增）

### 14.1 产后过渡期

分娩完成后，**不需要额外的"产后过渡"状态标签**。母亲的生理状态自然驱动她的行为：

```
分娩完成后的母亲生理状态:
  体力: 极低（≈1-2）
  疲劳度: 很高（≈8-9）
  饥饿度: 偏高
  健康值: 下降了1点

Step 4（欲望计算）读到这些生理状态 → 自然驱动策略:
  体力低、疲劳高 → want_rest（想休息）← 最高优先级
  饥饿度高 → want_eat（想吃）
  
  同时读到知识库: "我的孩子刚出生"
  → want_care_for_newborn（想守着孩子）← 与休息竞争

所以母亲接下来几天的行为:
  1. 躺床上休息（want_rest 获胜）
  2. 饿了 → 起来吃东西
  3. 婴儿哭了（感知到哭声）→ want_care_for_child 触发 → 去喂奶/安抚
  4. 吃完继续休息
  5. 体力恢复后 → 恢复正常活动 + 照料孩子成为常规欲望
```

这不需要任何"产后过渡期"的特殊代码——**就是生理数据驱动的自然决策**。

### 14.2 哺乳机制

```
哺乳期专属生理参数:
  母乳值: 0~100

母乳值变化:
  分娩完成后初始值: 60
  每 Tick（产后前3天）: +0.5（身体大量产奶）
  3天后: 每 Tick 无特殊变化，只在需要时计算
  
  喂奶时: 母乳值 -20（每次）
  不喂奶时: 缓慢累积（上限100）
  产后30天后: 母乳值逐渐下降（-0.1/天），模拟自然断奶
```

### 14.3 照料链条：婴儿哭 → 母亲喂奶

```
完整流程（多个 Tick 内完成）:

Tick N:
  婴儿 Step 3（或本能循环）:
    饥饿度自然上升 → 饥饿度 > 5

  婴儿 Step 3.5（本能反应）:
    触发本能: 哭
    → 产生听觉事件 { 类型: "婴儿哭声", 来源: baby.id, 半径: 40格 }

Tick N+1:
  母亲 Step 2（感知）:
    听到哭声 → 引擎查映射表: 哭声来源 system_id → 母亲的辨识符 r_child_01
    → 母亲.知识库: 追加一条"孩子正在哭"
  
  母亲 Step 3（生理推演）:
    母乳值 +0.5（产后产奶）
  
  母亲 Step 4（欲望计算）:
    读到: 知识库 "孩子正在哭" + "这是我的孩子"
    读到: 生理状态 母乳值 > 0
    触发欲望: want_feed_baby
    生成目标: action_feed_baby
  
  母亲 Step 5（行动执行）:
    执行 action_feed_baby:
      - 移动到婴儿旁边（1格内）
      - 如果有母乳: {
          婴儿.饥饿度 -5
          婴儿.开心值 +2
          母亲.母乳值 -20
          母亲.开心值 +2
        }
      - 如果没有母乳 且 物品栏有"奶粉": {
          用奶粉喂
          婴儿.饥饿度 -4
          母亲.物品栏.奶粉 -1
        }
      - 如果都没有: {
          婴儿哭声半径扩大（更响）
          母亲.压力值 +1
        }

  婴儿:
    被喂饱了 → 睡觉（本能: 疲劳度高 → 睡）
```

### 14.4 照料链条断了怎么办？

```
如果母亲不在家/母亲死亡/母亲没有母乳:

备选方案:
  1. 父亲（如果知识库里有"这是我的孩子" + 物品栏有奶粉）
  2. 其他家庭成员（祖父母）
  3. 附近有同理心的 NPC（孤儿救助机制，已有出生系统 §10.3）
  4. 都没有 → 婴儿持续饥饿 → 3天后饿死

这完全由信息壁垒决定——只有知道这个孩子存在的人才会去救。
```
