## 接口设计

### LLM请求格式

```json
{
  "请求id": "llm_001",
  "角色id": "npc_01",
  "上下文": {
    "当前状态": {},
    "周围环境": {},
    "记忆摘要": [],
    "性格描述": ""
  },
  "任务类型": "决策/对话/描述",
  "输入": "玩家正在观察你，请描述你的心理活动"
}
```

### LLM响应格式

```json
{
  "请求id": "llm_001",
  "角色id": "npc_01",
  "输出": {
    "心理活动": "今天天气不错，该去田里看看了...",
    "决策": {
      "动作": "移动",
      "目标": "农田区域"
    }
  }
}
```

## 效用AI与LLM对接

### 输出转换

LLM的输出需要转换为效用AI可理解的格式：

```python
def 转换LLM输出(llm响应):
    if llm响应.任务类型 == "决策":
        return {
            "动作类型": llm响应.输出.决策.动作,
            "目标": llm响应.输出.决策.目标,
            "来源": "LLM"
        }
    elif llm响应.任务类型 == "对话":
        return {
            "对话内容": llm响应.输出.对话,
            "来源": "LLM"
        }
```

### 优先级处理

```python
def 执行决策(角色):
    if 角色.llm接管 and 有LLM响应(角色):
        决策 = 获取LLM决策(角色)
    else:
        决策 = 效用AI决策(角色)
    
    执行动作(角色, 决策)
```

## 成本控制

### 调用限制

| 限制项 | 默认值 | 说明 |
|--------|--------|------|
| 每分钟调用次数 | 10 | 防止过度调用 |
| 单次响应超时 | 5秒 | 超时回退效用AI |
| 每日总调用次数 | 1000 | 控制成本 |

### 回退机制

当LLM调用失败或超时时，自动回退到效用AI：

```python
def 获取决策(角色):
    if 应该调用LLM(角色):
        try:
            return 调用LLM(角色)
        except 超时或错误:
            return 效用AI决策(角色)
    else:
        return 效用AI决策(角色)
```
