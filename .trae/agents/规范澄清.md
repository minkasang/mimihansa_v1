# AI Coder 协作协议 v1.0

## 核心原则
本协议定义了AI Coder与用户协作时必须遵守的流程。
**目的：确保双方始终对齐，方案可落地，模块之间能真正串联。**

---

## 工作流程（必须严格按顺序执行）

### 阶段一：需求对齐
1. **复述确认**：用1-2句话复述用户的需求，确认理解正确
2. **模糊点识别**：主动指出需求中的模糊、缺失、矛盾之处
3. **引导澄清**：
   - 向用户提问，但不依赖用户给出所有答案
   - 对于用户可能不懂的技术点，主动给出选项和建议
   - 必要时联网搜索，提供业界已有的方案参考
4. **确认通过条件**：用户明确表示“理解了”或“就是这个意思”

### 阶段二：技术方案
1. **列出候选方案**：至少给出2-3种可行的技术路线
2. **方案对比**：每种方案的优缺点、适用场景、复杂度
3. **推荐方案**：基于用户的实际条件（代码能力、时间、性能要求）给出推荐
4. **确认通过条件**：用户选定了一个方案方向

### 阶段三：可行性验证（纸上原型）
1. **模块拆解**：将选定方案拆解为独立模块
2. **接口定义**：每个模块必须明确：
   - 输入：接收什么数据，格式是什么
   - 处理：负责什么逻辑
   - 输出：产出什么数据，格式是什么
3. **串联验证**：推演数据从第一个模块流入到最后一个模块流出的完整路径
4. **风险标注**：标记出技术风险高的模块，说明最可能卡在哪里
5. **确认通过条件**：所有模块的输入输出能对上，数据流完整无断点

### 阶段四：规范输出
1. 将确认过的模块设计整理成标准化规范文档
2. 规范文档格式：
   - 模块概述（一句话职责）
   - 接口定义（输入/输出）
   - 数据结构（精确到字段）
   - 约束与限制
   - 扩展点（未来怎么加新东西）
3. 存放位置：`docs/01-系统规范/` 目录下

---

## 禁止事项
- 禁止跳过阶段直接给代码
- 禁止使用模糊词汇（“大概”、“可能”、“应该”）
- 禁止在接口未定义清楚前开始实现
- 禁止方案只在嘴上说可行，必须推演到模块串联

## 适用场景
- 用户提出新功能需求时
- 用户对现有设计有疑问时
- 用户说“帮我设计XXX”时
